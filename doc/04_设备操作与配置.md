# SlimeVR Tracker nRF 固件 - 设备操作与配置指南

## 1. 用户界面和反馈机制

### 1.1 LED 状态指示

LED 提供实时的设备状态反馈，无需打开控制台：

```
LED 闪烁模式 (由 led.c 管理):

初始化/启动阶段:
  ├─ 快速闪烁 (100 ms ON, 100 ms OFF)
  │   └─ 原因: 系统启动中，正在初始化
  │
  ├─ 缓慢闪烁 (500 ms ON, 500 ms OFF)
  │   └─ 原因: 启动完毕，等待配对或连接
  │
  └─ 混合闪烁 (长闪+短闪)
      └─ 原因: 在按钮持有期间，指示配对重置即将发生

连接阶段:
  ├─ 持续 ON (常亮)
  │   └─ 原因: 已连接到主站，数据传输中
  │
  └─ 间歇 ON (1 Hz)
      └─ 原因: 搜索信号，未连接

错误状态:
  ├─ 快速闪烁 (50 ms on/off)
  │   └─ 原因: IMU 检测失败或初始化错误
  │
  └─ 3 个短闪 + 暂停
      └─ 原因: 电池低电量

关机/睡眠:
  └─ 完全关闭
      └─ 原因: SYSTEM_OFF 模式或断电
```

**LED 颜色 (RGB 设备)**:
```
配置 (src/led.c):
  CONFIG_LED_DEFAULT_COLOR_R = 4000   // 红
  CONFIG_LED_DEFAULT_COLOR_G = 6000   // 绿
  CONFIG_LED_DEFAULT_COLOR_B = 0      // 蓝
  
  排列示例: 黄色 = 红+绿, 青色 = 绿+蓝

状态颜色:
  ├─ 绿色: 正常运行
  ├─ 黄色 (红+绿): 正在初始化或寻找信号
  ├─ 蓝色: 配对模式
  └─ 红色: 错误或电池低
```

### 1.2 按钮操作

按钮 (GPIO `sw0`, 如果存在) 支持多种操作：

```
按钮事件处理 (system.c / button_thread):

启动时 (在 main.c 中):
  ├─ 短按 (< 5 秒)
  │   └─ 动作: 继续正常启动，LED 一次闪烁确认
  │
  ├─ 中按 (5-10 秒)
  │   ├─ LED: 长闪，然后
  │   ├─ 动作: 调用 esb_reset_pair()
  │   │   └─ 清除配对地址从 EEPROM
  │   │   └─ 重置 RF 频道为默认
  │   │   └─ 继续启动 (现在处于"未配对"状态)
  │   └─ 用途: 准备与新的主站配对
  │
  └─ 长按 (> 10 秒) + USB 连接
      ├─ LED: 持续亮 + 快速闪烁
      ├─ 动作: 设置 DFU_DBL_RESET_MEM = DFU_DBL_RESET_APP
      └─ 动作: 触发重启，进入 Bootloader (DFU 模式)

运行时 (在 ACTIVE 模式中):
  ├─ 短按 (< 0.5 秒)
  │   ├─ 如果配置了 CONFIG_USER_EXTRA_ACTIONS
  │   ├─ 动作: LED 闪烁反馈
  │   └─ 用途: 确认用户输入，可用于自定义操作
  │
  └─ 长按 (> 5 秒, 当 CONFIG_USER_SHUTDOWN = y)
      ├─ 动作: sys_request_system_off()
      ├─ 结果: 系统进入 SYSTEM_OFF (深度睡眠)
      ├─ 唤醒: 按钮再次按下 (按钮配置为中断源)
      └─ 用途: 手动省电关机

按钮中断配置 (system.c):
  gpio_pin_interrupt_configure_dt(&sw0_spec, GPIO_INT_EDGE_FALLING);
  // 在按钮按下时生成中断
  
  gpio_add_callback(&sw0_spec, button_callback);
  // 触发 button_thread 处理
```

## 2. 控制台命令接口

### 2.1 控制台访问方式

该设备通过两个接口公开交互式控制台：

**接口 1: UART (串行端口)**
```
硬件: UART0 或 UART1 (基于板型)
波特率: 115200 baud
数据位: 8
停止位: 1
奇偶校验: 无

连接: 
  • USB-TTL 转接器连接到 TX/RX 引脚
  • 或 MCU 的原生 USB-to-UART

使用示例 (Linux/Mac):
  screen /dev/ttyUSB0 115200
  # 或
  minicom -D /dev/ttyUSB0 -b 115200
  
使用示例 (Windows):
  • PuTTY: 连接地址 COM*, 速率 115200
  • 或 TeraTerm
```

**接口 2: USB CDC-ACM (虚拟 COM 口)**
```
硬件: 内部 USB 设备 (HID + CDC-ACM)
VID: 0x1209 (OpenMoko)
PID: 0x7692 (SlimeVR)

连接:
  • 直接 USB 电缆到计算机
  • Windows: 自动创建虚拟 COM 口 (COM*)
  • Linux: /dev/ttyACM0 或 /dev/ttyACM1
  • macOS: /dev/tty.usbmodem*

使用示例:
  screen /dev/ttyACM0 115200
  # 或 (Linux)
  picocom /dev/ttyACM0 -b 115200
```

### 2.3 常用命令详解

#### `battery`
```bash
> battery

Battery: 3.8V (65%)
Avg: 3.75V

Min: 3.2V  Max: 4.1V
```

解释:
- **3.8V**: 当前实时电压
- **65%**: 基于电池曲线的容量百分比
- **Avg**: 24 样本的滑动平均
- **Min/Max**: 本次关电后的最低/最高

#### `status`
```bash
> status

Status Flags:
  Battery: OK (3.8V)
  Connected: YES (signal strength 80%)
  Sensor: OK (IMU found)
  Mag: OK (enabled)
  Button: RELEASED
  Fusion: VQF
```

解释:
- 列出所有系统状态标志
- 快速检查各子系统健康状态

#### `fusion`
```bash
> fusion

Quaternion: [0.9999, 0.0045, -0.0032, 0.0001]
Linear Accel: [0.05, -0.12, 0.03] m/s²

Gyro Bias: [0.001, -0.002, 0.003] rad/s
Temperature: 25.3°C

Fusion Algorithm: VQF
```

解释:
- **Quaternion**: 当前设备方向 [w, x, y, z]
  - 接近 [1, 0, 0, 0] 表示水平放置
- **Linear Accel**: 扣除重力后的真实加速度
- **Gyro Bias**: 陀螺零偏 (应该接近 0)
- **Temperature**: 传感器温度 (用于 T-Cal)

#### `sensor_debug`
```bash
> sensor_debug on

Sensor Debug: ENABLED (output every 1000 samples)

[SENSOR] Accel: [0.05, 0.12, 9.81] m/s²
[SENSOR] Gyro: [0.01, -0.02, 0.03] rad/s
[SENSOR] Mag: [20.1, 5.3, 40.2] µT (raw)
...
```

解释:
- `on`: 启用，默认每 1 秒 (1000 样本) 输出一次
- `every_n`: 每 N 个样本输出一次
- 用于调试传感器噪声和校准数据

#### `tcal status`
```bash
> tcal status

T-Cal Status:
  Points collected: 15 / 32
  Temperature range: 15°C - 35°C
  Polynomial degree: 2
  State: In progress
```

解释:
- 显示采集的温度校准点数
- 温度覆盖范围
- 多项式拟合度数
- 当前状态 (进行中/完成/未启用)

#### `dfu`
```bash
> dfu

Entering DFU mode...
[DFU] MSD ready, drag-and-drop firmware file
```

解释:
- 立即进入固件更新模式
- 设备会显示为外部存储设备 (UF2 格式)
- 将新的 `*.uf2` 文件拖放到虚拟驱动器

## 3. 固件更新 (DFU) 流程

### 3.1 进入 DFU 模式的三种方式

**方式 1: 快速按钮 + USB (最常用)**
```
1. 插入 USB 电缆 (保持连接)
2. 在 10 秒内短按按钮 5 次
   • LED 会快速闪烁
3. 系统进入 DFU，磁盘出现

用途: 快速更新，无需物理按钮持续
```

**方式 2: 按钮长按 + USB**
```
1. 插入 USB 电缆
2. 按住按钮直到 LED 指示 (通常 5-10 秒)
   • LED 持续亮 + 快速闪烁
3. 释放按钮，进入 DFU

用途: 明确的按钮反馈
```

**方式 3: 控制台命令**
```
1. 通过 USB 或 UART 连接控制台
2. 输入: dfu
3. 结果: 立即重启进入 DFU

用途: 远程或自动化更新
```

### 3.2 固件文件准备

**UF2 格式** (Adafruit Bootloader):
```
下载预编译的 *.uf2 文件 (或自己编译)

编译生成 UF2:
  west build -b [board] -- -DCONFIG_BUILD_OUTPUT_UF2=y
  # 输出: build/zephyr/app_update.uf2

复制流程:
  1. 进入 DFU 模式
  2. 磁盘 "SLIMEVR" 或类似挂载
  3. 拖放 app_update.uf2 到磁盘
  4. 设备自动重启，新固件激活
```

**二进制格式** (nRF5 Bootloader):
```
下载 *.bin 文件或使用 nrfutil

更新步骤:
  nrfutil dfu serial -pkg firmware.zip -p COM*
  # 或
  nrfutil pkg generate --dfu-image firmware.bin firmware.zip
  nrfutil dfu serial -pkg firmware.zip -p /dev/ttyACM0
```

### 3.3 DFU 故障排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 无法进入 DFU | USB 驱动未安装 | 安装 nRF USB 驱动程序 |
| 磁盘不显示 | Bootloader 损坏 | 使用 J-Link 恢复 Bootloader 镜像 |
| 更新后卡启动 | 固件与 Bootloader 不兼容 | 恢复上一版本，检查日志 |
| 无法识别 USB | 芯片损坏或 USB 电路故障 | 检查硬件连接，尝试不同 USB 端口 |

## 4. 配置项与可定制参数

### 4.1 用户可配置的主要参数

大多数参数在编译时通过 `Kconfig` 或 `prj.conf` 设置，但某些可以通过命令行或配置文件改变。

#### 运行时可改变的参数

目前固件中，以下参数可通过 NVS (非易失性存储) 改变：

```c
// src/system/system.c - NVS 键存储

nvs_keys:
  ├─ "paired_addr"      // 配对的主站地址 (8 字节)
  │                      // 清除: esb_reset_pair()
  │
  ├─ "rf_channel"       // RF 频道 (0-100, 默认 84)
  │                      // 改变: esb_set_channel(new_channel)
  │
  ├─ "gyro_offset"      // 陀螺零偏校准 (12 字节 = 3×float)
  │                      // 改变: 通过 T-Cal 或手动
  │
  └─ "mag_enabled"      // 磁力计启用标志 (1 字节)
                         // 改变: 通过控制台或编程
```

**注意**: 这些参数在固件中硬编码，若需更改，通常需要重新编译。

#### 编译时配置参数

这些参数在 `prj.conf` 或 board-specific `.conf` 中设置：

```kconfig
# 电源管理
CONFIG_ACTIVE_TIMEOUT_DELAY=180000      # 3 分钟 → 低功耗
CONFIG_SENSOR_LP_TIMEOUT=3600000        # 1 小时 → 深度睡眠
CONFIG_USE_IMU_WAKE_UP=y                # 启用运动唤醒

# 传感器采样
CONFIG_SENSOR_GYRO_ODR=400              # 陀螺频率 (Hz)
CONFIG_SENSOR_MAG_ODR=100               # 磁力计频率 (Hz)
CONFIG_SENSOR_ACCEL_FS=16               # 加速度范围 (g)
CONFIG_SENSOR_GYRO_FS=4000              # 陀螺范围 (dps)

# 校准
CONFIG_SENSOR_USE_6_SIDE_CALIBRATION=y  # 启用 6 边校准
CONFIG_SENSOR_USE_TCAL=y                # 启用温度校准
CONFIG_SENSOR_POLY_DEGREE=2             # T-Cal 多项式次数

# 用户操作
CONFIG_USER_SHUTDOWN=y                  # 启用手动关机
CONFIG_USER_EXTRA_ACTIONS=y             # 启用多按钮功能

# LED
CONFIG_LED_DEFAULT_COLOR_R=4000         # 红
CONFIG_LED_DEFAULT_COLOR_G=6000         # 绿
CONFIG_LED_DEFAULT_COLOR_B=0            # 蓝

# 无线电
CONFIG_RADIO_RF_CHANNEL=84              # 默认 RF 频道
CONFIG_RADIO_TX_POWER=8                 # 发射功率 (dBm)

# 看门狗
CONFIG_TASK_WDT_CHANNELS=8              # 看门狗通道数
CONFIG_TASK_WDT_HW_FALLBACK_DELAY=5000  # 硬件超时 (ms)
```

### 4.2 板级配置

每块板卡有对应的 overlay 文件 (`boards/*.overlay`) 定义硬件引脚和传感器选择：

```dtsi
// 例如: boards/xiao_ble_nrf52840_sense.overlay

&pinctrl {
    imu_i2c_default: imu_i2c_default {
        group1 {
            psels = <NRF_PSEL(TWIM_SDA, 0, 16)>,
                    <NRF_PSEL(TWIM_SCL, 0, 17)>;
        };
    };
    
    button_default: button_default {
        group1 {
            psels = <NRF_PSEL(GPIO_IN, 1, 1)>;  // P1.01
            bias-pull-up;
        };
    };
    
    led_pwm_default: led_pwm_default {
        group1 {
            psels = <NRF_PSEL(PWM_OUT0, 0, 26)>,  // Red
                    <NRF_PSEL(PWM_OUT1, 0, 30)>,  // Green
                    <NRF_PSEL(PWM_OUT2, 1, 9)>;   // Blue
        };
    };
};

// 传感器选择
&i2c0 {
    compatible = "nordic,nrf-twim";
    
    imu: bmi270@68 {
        compatible = "bosch,bmi270";
        reg = <0x68>;
    };
    
    mag: qmc6309@1c {
        compatible = "qst,qmc6309";
        reg = <0x1c>;
    };
};
```

修改这些文件需要重新编译固件。

### 4.3 在板卡间迁移配置

```bash
# 步骤1: 备份当前板卡的配置
cp boards/current_board/*.conf boards/current_board.conf.bak
cp boards/current_board/*.overlay boards/current_board.overlay.bak

# 步骤2: 比较目标板卡的配置
diff boards/current_board.conf boards/target_board.conf

# 步骤3: 根据需要调整参数
# 手动复制相关参数到 prj.conf

# 步骤4: 编译新板卡
west build -b target_board -p

# 步骤5: 刷写并验证
# (使用 J-Link, Bootloader 或其他工具)
```

## 5. 故障排查指南

### 5.1 常见问题与解决方案

| 症状 | 可能原因 | 解决步骤 |
|------|---------|----------|
| **LED 快速闪烁 + 不响应** | IMU 检测失败 | 1. 检查 I2C 接线<br>2. 验证 WHO_AM_I 寄存器<br>3. 更新 IMU 驱动 |
| **LED 缓慢闪烁，不连接** | 未配对或主站不在线 | 1. 长按按钮 5 秒重置配对<br>2. 检查主站软件<br>3. 查看 RF 频道是否匹配 |
| **连接不稳定，频繁断线** | 信号干扰，RF 功率不足 | 1. 增加 TX_POWER<br>2. 更改 RF 频道<br>3. 检查 2.4GHz 干扰 (WiFi) |
| **电池显示 100%，不下降** | 电池监控禁用或校准错误 | 1. 检查 CONFIG_BATTERY_*_MAPPING<br>2. 运行 `battery` 命令<br>3. 验证 ADC 接线 |
| **四元数不变化** | 加速度校准缺失或损坏 | 1. 运行 6 边加速度校准<br>2. 检查 retained_data<br>3. 尝试恢复出厂设置 |
| **温度校准失败** | 温度范围不足或采集时间太短 | 1. 在更宽的温度范围内重新运行<br>2. 确保设备静止<br>3. 运行 `tcal clear` 再重试 |
| **USB 不识别** | 驱动程序缺失或硬件故障 | 1. 安装平台驱动 (nRF USB)<br>2. 尝试不同 USB 端口<br>3. 检查 USB 线缆 |
| **无法进入 DFU** | Bootloader 损坏或快速重启计数错误 | 1. 手动重置：清除 flash<br>2. 恢复 Bootloader 固件<br>3. 使用 J-Link 编程 |

### 5.2 日志级别调整

日志级别通过 `Kconfig` 控制，可选值：

```kconfig
CONFIG_LOG_LEVEL_OFF=0

# 特定模块日志
```

## 6. 性能优化建议

### 6.1 功耗优化

```
场景 1: 长期穿戴 (8+ 小时)
  ├─ CONFIG_ACTIVE_TIMEOUT_DELAY=180000   (3 分钟)
  ├─ CONFIG_USE_IMU_WAKE_UP=y            (启用 WOM)
  ├─ CONFIG_WOM_USE_DCDC=n               (LDO 更低功耗)
  ├─ CONFIG_SENSOR_MAG_ODR=100           (较低频率)
  └─ 预期续航: 24-48 小时

场景 2: 高精度实时追踪
  ├─ CONFIG_ACTIVE_TIMEOUT_DELAY=3600000 (1 小时)
  ├─ CONFIG_USE_IMU_WAKE_UP=n            (禁用 WOM)
  ├─ CONFIG_WOM_USE_DCDC=y               (DCDC 性能)
  ├─ CONFIG_SENSOR_GYRO_ODR=800          (高采样率)
  └─ 预期续航: 5-8 小时 (权衡功耗)

场景 3: 开发和调试
  ├─ CONFIG_LOG_LEVEL_DBG=y              (详细日志)
  ├─ CONFIG_SENSOR_RANGE_STATS=y         (范围统计)
  ├─ 禁用自动低功耗转换
  └─ 预期续航: 2-3 小时
```

### 6.2 延迟和响应时间优化

```
最小化四元数延迟:
  ├─ CONFIG_SENSOR_GYRO_ODR=400          (足够高的采样率)
  │   (更高的 ODR 不会改善延迟，反而增加功耗)
  │
  ├─ 优化 VQF 参数
  │   ├─ setGyrAccTime = 0.2            (快速响应 )
  │   └─ setMagTime = 0.5               (稳定磁力计)
  │
  └─ 禁用日志 (可能影响)
      └─ CONFIG_LOG_BACKEND_UART_AUTOSTART=n

典型延迟:
  ├─ 传感器到融合: 1-2 ms
  ├─ 融合到 ESB 发送: 1-2 ms
  ├─ 空中传输: 0.5-1 ms (短距离)
  └─ 总计: ~3-5 ms
```

### 6.3 精度优化

```
步骤 1: 校准
  ├─ 运行 6 边加速度校准 (见 03_传感器与算法.md)
  ├─ 运行温度校准 (T-Cal)
  └─ 验证校准数据不为零

步骤 2: 振动隔离
  ├─ 在设备上使用减振垫
  ├─ 避免强烈的机械振动
  └─ 远离高功率电机和扬声器

步骤 3: 磁场管理
  ├─ 避免强磁场 (磁铁、金属物品)
  ├─ 距离大型金属结构 > 1 米
  └─ 在 GPS 接收器附近工作时注意

步骤 4: 算法调整
  ├─ 增加 tauAcc (更信任重力，抗噪)
  ├─ 增加 tauMag (更信任磁北，抗干扰)
  └─ 根据具体应用场景平衡
```


```
  ├─ 高速旋转 (> 500°/s): ±5-10°
  └─ 偏航稳定性: ±1-2° (无磁干扰)

延迟:
  ├─ 传感器读取: 2.5 ms (400 Hz 周期)
  ├─ 融合处理: 1.0 ms
  ├─ 无线传输: 1.0 ms
  └─ 总端到端: 4-5 ms

功耗:

  ├─ LPM1 (WOM): 0.8-1.5 mA
  ├─ LPM2: < 0.5 mA

  └─ 标准锂电池 (500 mAh): 30-50 小时待机

吞吐量:
  ├─ 四元数 + 加速度: 400 Hz

通信可靠性:
  ├─ BER 反应: < 0.01% (典型)
  ├─ 丢包率: < 1% (良好信号)

  └─ 自动重连: 是
```
