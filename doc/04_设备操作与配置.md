# SlimeVR Tracker nRF 固件 - 设备操作与配置指南

## 1. 用户界面和反馈机制

### 1.1 LED 状态指示

LED 提供实时的设备状态反馈，无需打开控制台：

```
LED 闪烁模式 (由 led.c 管理):

初始化/启动阶段:
  ├─ 快速闪烁 (100 ms ON, 100 ms OFF)
  │   └─ 原因: 系统启动中，正在初始化
  │
  ├─ 缓慢闪烁 (500 ms ON, 500 ms OFF)
  │   └─ 原因: 启动完毕，等待配对或连接
  │
  └─ 混合闪烁 (长闪+短闪)
      └─ 原因: 在按钮持有期间，指示配对重置即将发生

连接阶段:
  ├─ 持续 ON (常亮)
  │   └─ 原因: 已连接到主站，数据传输中
  │
  └─ 间歇 ON (1 Hz)
      └─ 原因: 搜索信号，未连接

错误状态:
  ├─ 快速闪烁 (50 ms on/off)
  │   └─ 原因: IMU 检测失败或初始化错误
  │
  └─ 3 个短闪 + 暂停
      └─ 原因: 电池低电量

关机/睡眠:
  └─ 完全关闭
      └─ 原因: SYSTEM_OFF 模式或断电
```

**LED 颜色 (RGB 设备)**:
```
配置 (src/led.c):
  CONFIG_LED_DEFAULT_COLOR_R = 4000   // 红
  CONFIG_LED_DEFAULT_COLOR_G = 6000   // 绿
  CONFIG_LED_DEFAULT_COLOR_B = 0      // 蓝
  
  排列示例: 黄色 = 红+绿, 青色 = 绿+蓝

状态颜色:
  ├─ 绿色: 正常运行
  ├─ 黄色 (红+绿): 正在初始化或寻找信号
  ├─ 蓝色: 配对模式
  └─ 红色: 错误或电池低
```

### 1.2 按钮操作

按钮 (GPIO `sw0`, 如果存在) 支持多种操作：

```
按钮事件处理 (system.c / button_thread):

启动时 (在 main.c 中):
  ├─ 短按 (< 5 秒)
  │   └─ 动作: 继续正常启动，LED 一次闪烁确认
  │
  ├─ 中按 (5-10 秒)
  │   ├─ LED: 长闪，然后
  │   ├─ 动作: 调用 esb_reset_pair()
  │   │   └─ 清除配对地址从 EEPROM
  │   │   └─ 重置 RF 频道为默认
  │   │   └─ 继续启动 (现在处于"未配对"状态)
  │   └─ 用途: 准备与新的主站配对
  │
  └─ USB 控制台初始化时按住按钮
      ├─ 动作: 设置普通 UF2 DFU magic
      └─ 动作: 触发重启，进入 Bootloader (DFU 模式)

运行时 (在 ACTIVE 模式中):
  ├─ 短按 (< 0.5 秒)
  │   ├─ 默认动作: 软件重启
  │   └─ 多次短按: button_thread() 统计后调用 sys_reset_mode()
  │
  └─ 长按 (> 5 秒, 当 CONFIG_USER_SHUTDOWN = y)
      ├─ 动作: sys_user_shutdown()
      ├─ 结果: 系统进入 SYSTEM_OFF (深度睡眠)
      ├─ 唤醒: 按钮再次按下 (按钮配置为中断源)
      └─ 用途: 手动省电关机

代码对照:
  • src/main.c::main()
  • src/system/system.c::button_thread()
  • src/system/system.c::sys_reset_mode()
  • src/system/system.c::sys_user_shutdown()

按钮中断配置 (system.c):
  gpio_pin_interrupt_configure_dt(&button0, GPIO_INT_EDGE_BOTH);
  // 按下和释放都会生成中断
  
  gpio_add_callback(button0.port, &button_cb_data);
  // 触发 button_thread 处理
```

## 2. 控制台命令接口

### 2.1 控制台访问方式

该设备通过两个接口公开交互式控制台：

**接口 1: UART (串行端口)**
```
硬件: UART0 或 UART1 (基于板型)
波特率: 115200 baud
数据位: 8
停止位: 1
奇偶校验: 无

连接: 
  • USB-TTL 转接器连接到 TX/RX 引脚
  • 或 MCU 的原生 USB-to-UART

使用示例 (Linux/Mac):
  screen /dev/ttyUSB0 115200
  # 或
  minicom -D /dev/ttyUSB0 -b 115200
  
使用示例 (Windows):
  • PuTTY: 连接地址 COM*, 速率 115200
  • 或 TeraTerm
```

**接口 2: USB CDC-ACM (虚拟 COM 口)**
```
硬件: 内部 USB 设备 (HID + CDC-ACM)
VID: 0x1209 (OpenMoko)
PID: 0x7692 (SlimeVR)

连接:
  • 直接 USB 电缆到计算机
  • Windows: 自动创建虚拟 COM 口 (COM*)
  • Linux: /dev/ttyACM0 或 /dev/ttyACM1
  • macOS: /dev/tty.usbmodem*

使用示例:
  screen /dev/ttyACM0 115200
  # 或 (Linux)
  picocom /dev/ttyACM0 -b 115200
```

### 2.3 常用命令详解

#### `battery`
```bash
> battery

Battery: 3.8V (65%)
Avg: 3.75V

Min: 3.2V  Max: 4.1V
```

解释:
- **3.8V**: 当前实时电压
- **65%**: 基于电池曲线的容量百分比
- **Avg**: 24 样本的滑动平均
- **Min/Max**: 本次关电后的最低/最高

#### `info`
```bash
> info

IMU: ICM42688
Magnetometer: enabled
Accelerometer matrix:
...
Gyroscope bias: ...
Gyroscope bias tcal (real-time): ... at 25.30 C
Fusion: VQF
```

解释:
- `info` 是当前固件的主要人工检查入口
- 对照实现: `src/console.c::print_info()`
- 若开启 `CONFIG_SENSOR_RANGE_STATS`，输出中还会包含运行时范围统计摘要

#### `debug`
```bash
> debug 3

Sensor debug started for 3 seconds
...
```

解释:
- `debug [duration]` 会在 1-60 秒内以传感器 FIFO 路径输出调试数据
- 对照实现: `src/sensor/sensor.c::sensor_debug_start()`

#### `tcal status`
```bash
> tcal status

Temperature Calibration Status (MLS):
  - MLS available: Yes
  - Points collected: 15 / 70
  - LUT valid: Yes, state: Complete, entries: 71/71
  - Calibrated temp range: 20.25C to 32.75C

Boot/Runtime Calibration Status:
  - D_offset: [...]
  - Bias tracking mode: T-Cal + D_offset
```

解释:
- 当前 T-Cal 使用 MLS (Moving Least Squares) + LUT，不再使用运行时多项式拟合
- `tcal auto on` 后，设备静止时会自动采集温度点；`tcal clear` 与 `reset tcal` 都会清空温度校准
- 对照实现: `src/sensor/calibration.c::sensor_tcal_status()`、`sensor_tcal_feed_continuous_sample()`、`sensor_tcal_lut_lookup()`、`sensor_tcal_mls_lookup()`

#### `dfu` / `dfu ota`
```bash
> dfu

Entering UF2 DFU...

> dfu ota

Entering OTA DFU (BLE)...
```

解释:
- `dfu` 设置 Adafruit UF2 magic (`0x57`) 后重启，进入 USB/UF2 bootloader
- `dfu ota` 设置 Adafruit BLE OTA magic (`0xA8`) 后重启，进入 bootloader 的 BLE OTA 模式
- 对照实现: `src/console.c::console_thread()`；magic 常量在 `src/globals.h`

### 2.4 远程预置命令整理

接收器可通过 ESB PONG flags 下发远程预置命令。命令 ID 定义在 `src/connection/esb.h` 的 `ESB_PONG_FLAG_*`，接收/确认在 `src/connection/esb.c::event_handler()`，延迟执行在 `src/connection/esb.c::esb_thread()` 的远程命令 `switch` 中。

| ID | 预置命令 | 行为 | 文件 / 主要函数 |
|----|----------|------|----------|
| `0x00` | `NORMAL` | 普通 PONG，无远程动作；可携带 TDMA 配置 | `src/connection/esb.c::event_handler()` |
| `0x01` | `SHUTDOWN` | 请求关机 | `src/system/system.c::sys_command_shutdown()` |
| `0x02` | `CALIBRATE` | ZRO/静止零偏校准 | `src/sensor/calibration.c::sensor_request_calibration()` |
| `0x03` | `SIX_SIDE_CAL` | 6 面加速度校准 | `src/sensor/calibration.c::sensor_request_calibration_6_side()` |
| `0x04` | `MEOW` | 远程打印文本 | `src/connection/esb.c::remote_print_meow()` |
| `0x05` | `SCAN` | 重新扫描传感器 | `src/sensor/sensor.c::sensor_request_scan(true)` |
| `0x06` | `MAG_CLEAR` | 清除磁力计校准 | `src/sensor/calibration.c::sensor_calibration_clear_mag()` |
| `0x07` | `REBOOT` | 软件重启 | `src/system/power.c::sys_request_system_reboot(false)` |
| `0x08` | `CLEAR` | 清除配对数据 | `src/connection/esb.c::esb_clear_pair()` |

| `0x12` | `RESET_TCAL` | 清除温度校准 | `src/console.c::cmd_reset_tcal()` |
| `0x13` | `TCAL_AUTO_ON` | 开启自动 T-Cal 采集 | `src/sensor/calibration.c::sensor_tcal_set_auto_calibration(true)` |

## 3. 固件更新 (DFU) 流程

### 3.1 进入 DFU 模式的方式

**方式 1: 控制台命令**
```
1. 通过 USB CDC-ACM、UART 或 RTT 进入控制台
2. 输入 `dfu`：进入普通 USB/UF2 DFU
3. 输入 `dfu ota`：进入 BLE OTA DFU

代码对照:
  • src/console.c::console_thread()
  • src/globals.h::ADAFRUIT_DFU_MAGIC_UF2_RESET
  • src/globals.h::ADAFRUIT_DFU_MAGIC_OTA_RESET
```

**方式 2: 启动/USB 时按住按钮**
```
1. 插入 USB 电缆
2. 在 USB 控制台线程初始化时保持按钮按下
3. 固件设置 bootloader magic 并重启进入普通 DFU

代码对照:
  • src/console.c::console_thread()
```

**方式 3: 运行时按钮多按**
```
1. 运行时快速按键，button_thread() 在约 1 秒窗口内统计次数
2. 普通板卡: 4-5 次进入普通 DFU；Styria Mini UF2: 6-7 次进入普通 DFU
3. 8-9 次进入 BLE OTA DFU

代码对照:
  • src/system/system.c::button_thread()
  • src/system/system.c::sys_reset_mode()
```

**方式 4: 远程预置命令**
```
接收器下发 ESB_PONG_FLAG_DFU 或 ESB_PONG_FLAG_DFU_OTA。

代码对照:
  • src/connection/esb.h::ESB_PONG_FLAG_DFU
  • src/connection/esb.h::ESB_PONG_FLAG_DFU_OTA
  • src/connection/esb.c 远程命令 switch
```

**方式 5: 看门狗恢复路径**
```
连续 WDT 复位达到 WATCHDOG_RESET_THRESHOLD(当前为 3) 后，固件进入普通 DFU 用于恢复。

代码对照:
  • src/system/watchdog.h::WATCHDOG_RESET_THRESHOLD
  • src/system/watchdog.c::enter_dfu_mode()
```

### 3.2 固件文件准备

**USB/UF2 格式** (Adafruit Bootloader):
```
下载预编译的 *.uf2 文件 (或自己编译)

编译生成 UF2:
  west build -b [board] -- -DCONFIG_BUILD_OUTPUT_UF2=y
  # 输出: build/zephyr/app_update.uf2

复制流程:
  1. 进入 DFU 模式
  2. 磁盘 "SLIMEVR" 或类似挂载
  3. 拖放 app_update.uf2 到磁盘
  4. 设备自动重启，新固件激活
```

**BLE OTA** (Adafruit Bootloader):
```
进入方式:
  1. 控制台输入 `dfu ota`
  2. 或远程下发 `ESB_PONG_FLAG_DFU_OTA`

行为:
  • 应用固件只负责设置 GPREGRET=0xA8 并重启
  • 实际 BLE OTA 广播、连接和固件写入由 bootloader 完成
  • 需要使用与 bootloader 匹配的手机/桌面 OTA 工具和固件包格式

代码对照:
  • src/console.c::console_thread()
  • src/connection/esb.c 远程命令 switch
  • src/globals.h::ADAFRUIT_DFU_MAGIC_OTA_RESET
```

**二进制/串口格式** (nRF5 Bootloader):
```
下载 *.bin 文件或使用 nrfutil

更新步骤:
  nrfutil dfu serial -pkg firmware.zip -p COM*
  # 或
  nrfutil pkg generate --dfu-image firmware.bin firmware.zip
  nrfutil dfu serial -pkg firmware.zip -p /dev/ttyACM0
```

### 3.3 DFU 故障排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 无法进入 DFU | USB 驱动未安装 | 安装 nRF USB 驱动程序 |
| 磁盘不显示 | Bootloader 损坏 | 使用 J-Link 恢复 Bootloader 镜像 |
| `dfu ota` 后没有 BLE OTA 广播 | 当前板卡/构建不是 Adafruit UF2 bootloader，或 bootloader 不支持 OTA | 确认 `CONFIG_BUILD_OUTPUT_UF2=y` 和 bootloader 类型；对照 `src/console.c::console_thread()` |
| 更新后卡启动 | 固件与 Bootloader 不兼容 | 恢复上一版本，检查日志 |
| 无法识别 USB | 芯片损坏或 USB 电路故障 | 检查硬件连接，尝试不同 USB 端口 |

## 4. 配置项与可定制参数

### 4.1 用户可配置的主要参数

大多数参数在编译时通过 `Kconfig` 或 `prj.conf` 设置，但某些可以通过命令行或配置文件改变。

#### 运行时可改变的参数

目前固件中，以下参数可通过 NVS (非易失性存储) 改变。NVS 使用数字 ID，不使用字符串键；ID 定义在 `src/system/system.h`，读写入口是 `sys_read()` / `sys_write()`。

```c
// src/system/system.h
PAIRED_ID                     // 配对地址，clear/pair/set 会改变
RF_CHANNEL_ID                 // RF 频道，channel/clearchannel 会改变
MAIN_GYRO_BIAS_ID             // 静态陀螺零偏，calibrate/reset zro 会改变
MAIN_ACC_6_BIAS_ID            // 6 面加速度校准，6-side/reset acc 会改变
MAIN_MAG_BIAS_ID              // 磁力计偏移，mag cal/mag clear 会改变
MAG_ENABLED_ID                // 磁力计启用状态，mag on/off 会改变
MAIN_GYRO_TCAL_POINTS_ID      // T-Cal 温度点，tcal auto/dump/remove/clear 会改变
MAIN_GYRO_TCAL_STATE_ID       // T-Cal 状态，update_tcal_state() 写入
```

**注意**: 这些参数在固件中硬编码，若需更改，通常需要重新编译。

#### 编译时配置参数

这些参数在 `prj.conf` 或 board-specific `.conf` 中设置：

```kconfig
# 电源管理
CONFIG_ACTIVE_TIMEOUT_DELAY=180000      # 3 分钟 → 低功耗
CONFIG_SENSOR_LP_TIMEOUT=3600000        # 1 小时 → 深度睡眠
CONFIG_USE_IMU_WAKE_UP=y                # 启用运动唤醒

# 传感器采样
CONFIG_SENSOR_GYRO_ODR=400              # 陀螺频率 (Hz)
CONFIG_SENSOR_MAG_ODR=100               # 磁力计频率 (Hz)
CONFIG_SENSOR_ACCEL_FS=16               # 加速度范围 (g)
CONFIG_SENSOR_GYRO_FS=4000              # 陀螺范围 (dps)

# 校准
CONFIG_SENSOR_USE_6_SIDE_CALIBRATION=y  # 启用 6 边校准
CONFIG_SENSOR_USE_TCAL=y                # 启用温度校准
CONFIG_SENSOR_POLY_TEMP_MIN=10          # T-Cal 桶最低温度，Kconfig 默认
CONFIG_SENSOR_POLY_TEMP_MAX=45          # T-Cal 桶最高温度，Kconfig 默认
CONFIG_SENSOR_POLY_STEPS_PER_DEGREE=2   # 每摄氏度 2 个桶，即 0.5°C 间隔
# CONFIG_SENSOR_POLY_DEGREE 仍存在，但当前 MLS/LUT 路径不再使用多项式系数

# 用户操作
CONFIG_USER_SHUTDOWN=y                  # 启用手动关机
CONFIG_USER_EXTRA_ACTIONS=y             # 启用多按钮功能

# LED
CONFIG_LED_DEFAULT_COLOR_R=4000         # 红
CONFIG_LED_DEFAULT_COLOR_G=6000         # 绿
CONFIG_LED_DEFAULT_COLOR_B=0            # 蓝

# 无线电
CONFIG_RADIO_RF_CHANNEL=84              # 默认 RF 频道
CONFIG_RADIO_TX_POWER=8                 # 发射功率 (dBm)

# 看门狗
CONFIG_TASK_WDT_CHANNELS=8              # 看门狗通道数
CONFIG_TASK_WDT_HW_FALLBACK_DELAY=5000  # 硬件超时 (ms)
```

## 5. 故障排查指南

### 5.1 常见问题与解决方案

| 症状 | 可能原因 | 解决步骤 |
|------|---------|----------|
| **LED 快速闪烁 + 不响应** | IMU 检测失败 | 1. 检查 I2C 接线<br>2. 验证 WHO_AM_I 寄存器<br>3. 更新 IMU 驱动 |
| **LED 缓慢闪烁，不连接** | 未配对或主站不在线 | 1. 长按按钮 5 秒重置配对<br>2. 检查主站软件<br>3. 查看 RF 频道是否匹配 |
| **连接不稳定，频繁断线** | 信号干扰，RF 功率不足 | 1. 增加 TX_POWER<br>2. 更改 RF 频道<br>3. 检查 2.4GHz 干扰 (WiFi) |
| **电池显示 100%，不下降** | 电池监控禁用或校准错误 | 1. 检查 CONFIG_BATTERY_*_MAPPING<br>2. 运行 `battery` 命令<br>3. 验证 ADC 接线 |
| **四元数不变化** | 加速度校准缺失或损坏 | 1. 运行 6 边加速度校准<br>2. 检查 retained_data<br>3. 尝试恢复出厂设置 |
| **温度校准没有增加点数** | 未开启自动采集、设备不够静止、温度超出配置范围 | 1. 运行 `tcal auto on`<br>2. 保持设备静止并查看 `tcal status`/`tcal check`<br>3. 必要时 `tcal clear` 后重新采集<br>4. 对照 `src/sensor/calibration.c::sensor_tcal_feed_continuous_sample()` |
| **USB 不识别** | 驱动程序缺失或硬件故障 | 1. 安装平台驱动 (nRF USB)<br>2. 尝试不同 USB 端口<br>3. 检查 USB 线缆 |
| **无法进入 DFU** | Bootloader 损坏或快速重启计数错误 | 1. 手动重置：清除 flash<br>2. 恢复 Bootloader 固件<br>3. 使用 J-Link 编程 |

## 6. 性能优化建议

### 6.1 功耗优化

```
场景 1: 长期穿戴 (8+ 小时)
  ├─ CONFIG_ACTIVE_TIMEOUT_DELAY=180000   (3 分钟)
  ├─ CONFIG_USE_IMU_WAKE_UP=y            (启用 WOM)
  ├─ CONFIG_WOM_USE_DCDC=n               (LDO 更低功耗)
  ├─ CONFIG_SENSOR_MAG_ODR=100           (较低频率)
  └─ 预期续航: 24-48 小时

场景 2: 高精度实时追踪
  ├─ CONFIG_ACTIVE_TIMEOUT_DELAY=3600000 (1 小时)
  ├─ CONFIG_USE_IMU_WAKE_UP=n            (禁用 WOM)
  ├─ CONFIG_WOM_USE_DCDC=y               (DCDC 性能)
  ├─ CONFIG_SENSOR_GYRO_ODR=800          (高采样率)
  └─ 预期续航: 5-8 小时 (权衡功耗)

场景 3: 开发和调试
  ├─ CONFIG_LOG_LEVEL_DBG=y              (详细日志)
  ├─ CONFIG_SENSOR_RANGE_STATS=y         (范围统计)
  ├─ 禁用自动低功耗转换
  └─ 预期续航: 2-3 小时
```

### 6.2 延迟和响应时间优化

```
最小化四元数延迟:
  ├─ CONFIG_SENSOR_GYRO_ODR=400          (足够高的采样率)
  │   (更高的 ODR 不会改善延迟，反而增加功耗)
  │
  ├─ 优化 VQF 参数
  │   ├─ setGyrAccTime = 0.2            (快速响应 )
  │   └─ setMagTime = 0.5               (稳定磁力计)
  │
  └─ 禁用日志 (可能影响)
      └─ CONFIG_LOG_BACKEND_UART_AUTOSTART=n

典型延迟:
  ├─ 传感器到融合: 1-2 ms
  ├─ 融合到 ESB 发送: 1-2 ms
  ├─ 空中传输: 0.5-1 ms (短距离)
  └─ 总计: ~3-5 ms
```

### 6.3 精度优化

```
步骤 1: 校准
  ├─ 运行 6 边加速度校准 (见 03_传感器与算法.md)
  ├─ tcal auto on 后静止采集温度校准点
  ├─ 使用 tcal status / tcal test 验证 MLS/LUT 输出
  └─ 验证校准数据不为零

步骤 2: 振动隔离
  ├─ 在设备上使用减振垫
  ├─ 避免强烈的机械振动
  └─ 远离高功率电机和扬声器

步骤 3: 磁场管理
  ├─ 避免强磁场 (磁铁、金属物品)
  ├─ 距离大型金属结构 > 1 米
  └─ 在 GPS 接收器附近工作时注意

步骤 4: 算法调整
  ├─ 增加 tauAcc (更信任重力，抗噪)
  ├─ 增加 tauMag (更信任磁北，抗干扰)
  └─ 根据具体应用场景平衡
```

## 7. 高级主题

### 7.1 自定义 IMU/MAG 添加

如果需要支持新芯片，编辑 `src/sensor/sensors.h` 和添加驱动：

```c
// 1. 在 sensors.h 中添加枚举
enum SensorModel {
    // ...existing...
    SENSOR_MODEL_ICM_NEW_CHIP,
};

// 2. 在 imu/ 目录创建新驱动
// src/sensor/imu/icm_new_chip.c
int icm_new_chip_init(struct sensor_context *ctx) {
    // WHO_AM_I 检查
    // 寄存器初始化
    // 中断配置
}

// 3. 在 interface.c 的驱动表中注册
static const struct sensor_driver imu_drivers[] = {
    // ...existing...
    { .name = "ICM New Chip", .id = 0x???, .init = icm_new_chip_init, ... },
};
```

### 7.2 自定义融合算法

要使用不同的融合算法 (而非 VQF)，编辑 `src/sensor/fusion/fusions.h`:

```c
// 在 fusions.c 实现新的融合函数
int custom_fusion_init(void) { ... }
int custom_fusion_update(float *accel, float *gyro, float *mag, 
                         float dt, float *q_out) { ... }

// 在 sensor.c 运行时选择
#if CONFIG_SENSOR_USE_CUSTOM_FUSION
    fusion_init_func = custom_fusion_init;
    fusion_update_func = custom_fusion_update;
#endif
```

### 7.3 多设备同步 (TDMA)

该项目支持多个追踪器通过时分多址 (TDMA) 同步：

```c
// src/connection/tdma.c

tdma_slot(); // 获取当前时间槽
// 返回值可用于确定何时应该发送数据

// 每个追踪器 ID 映射到不同的时间槽
// 防止碰撞，允许同时操作多个跟踪器
```

## 8. 性能基准

该跟踪器的典型性能指标：

```
运动追踪精度:
  ├─ 静态定向: ±1-2°
  ├─ 动态旋转 (< 200°/s): ±2-5°
  ├─ 高速旋转 (> 500°/s): ±5-10°
  └─ 偏航稳定性: ±1-2° (无磁干扰)

延迟:
  ├─ 传感器读取: 2.5 ms (400 Hz 周期)
  ├─ 融合处理: 1.0 ms
  ├─ 无线传输: 1.0 ms
  └─ 总端到端: 4-5 ms

功耗:
  ├─ ACTIVE (正常): 12-15 mA
  ├─ LPM1 (WOM): 0.8-1.5 mA
  ├─ LPM2: < 0.5 mA
  ├─ SYSTEM_OFF: < 10 µA
  └─ 标准锂电池 (500 mAh): 30-50 小时待机

吞吐量:
  ├─ 四元数 + 加速度: 400 Hz
  ├─ 磁力计: 100 Hz (可选)
  ├─ ESB 数据包: 48 字节最大
  └─ 无线电范围: ~100 米 (直线视距)

通信可靠性:
  ├─ BER 反应: < 0.01% (典型)
  ├─ 丢包率: < 1% (良好信号)
  ├─ ACK 超时: 可配置 (默认 3 分钟)
  └─ 自动重连: 是
```
