# SlimeVR Tracker nRF 固件 - 工作模式与电源管理

## 1. 电源管理核心概念

### 1.1 设计目标
- 在保持高精度追踪的同时，最大化待机时间
- 支持从任何低功耗状态快速唤醒和进入活跃状态
- 最小化用户感知的延迟
- 支持多种唤醒源 (按钮、运动、USB 充电等)

### 1.2 管制部件

| 子系统 | 电流 (典型) | 可控性 |
|--------|-----------|--------|
| nRF52 Cortex-M4 CPU | 2-4 mA (活跃) | 通过频率降频或休眠 |
| 2.4GHz 无线电模块 | 10-15 mA (TX/RX) | 开/关无线电|
| IMU 传感器 | 1-2 mA (活跃) | 配置采样率或停用 |
| 磁力计 | 0.5-1 mA | 按需启用 |
| DCDC 稳压器 | 低静态电流 | 切换至 LDO |
| LDO 稳压器 | 中等静态电流 | 用于低功耗模式 |
| 深度睡眠 (系统关机) | < 10 µA | 系统全部关闭 |

## 2. 电源模式详解

### 2.1 ACTIVE 模式 (活跃运行模式)

**启用条件**:
- 系统刚启动
- 从低功耗模式唤醒后立即进入
- 已连接到主站或主动尝试连接

**工作配置**:
```c
电源状态
  ├─ CPU 频率: 64 MHz (常规)
  ├─ 无线电: 连续轮询/接收于 400 Hz IMU 速率
  ├─ IMU: 400 Hz 采样 (陀螺 + 加速)
  ├─ 磁力计: 100 Hz 采样 (如启用)
  ├─ 稳压器: DCDC (高效率)
  └─ 其他: 所有 GPIO 和外设启用

时序
  ├─ 传感器读取间隔: 2.5 ms (400 Hz)
  ├─ 数据融合时间: < 1 ms (VQF)
  ├─ ESB 发送: 异步 (2.5 ms 可用)
  └─ 功耗: ~12-15 mA (含无线电)
```

**状态转换条件**:
```
ACTIVE → LPM1/WOM:
  ├─ 无收到新的传感器触发 3 分钟 (CONFIG_ACTIVE_TIMEOUT_DELAY = 180s)
    AND
  ├─ 已启用 IMU 唤醒 (CONFIG_USE_IMU_WAKE_UP = y)
    AND
  ├─ 不在配对模式 (status_flags.pairing == false)
    AND
  └─ 无待处理的错误标志

主要事件驱动:
  ├─ 按钮按下 → 重置超时计时器
  ├─ IMU 检测到强加速度 → 重置超时计时器
  └─ ESB 心跳包 (Ping) 失败 3 分钟 → 切换至 WOM
```

### 2.2 LPM1 (低功耗模式 1 - 运动唤醒模式)

**启用条件**:
- 3 分钟无活动
- 已启用 IMU 唤醒功能 (`CONFIG_USE_IMU_WAKE_UP = y`)
- 不在配对或连接仲裁阶段

**工作配置**:
```c
电源状态
  ├─ CPU: 睡眠 (深度睡眠周期)
  ├─ 无线电: 关闭 (不发送/接收)
  ├─ IMU: 
  │   ├─ 陀螺: 400 Hz (保持配置，但不读取)
  │   ├─ 加速度: 12.5 Hz (超低采样，仅用于 WOM)
  │   └─ WOM 中断: 启用 (连接到 INT0 GPIO)
  ├─ 磁力计: 停用
  ├─ 稳压器: LDO (低漏电流)
  └─ GPIO: 仅 INT0 (WOM) 和电源GPIO启用

功耗: ~0.8-1.5 mA (主要来自 LDO 和 IMU 待机)

时序
  ├─ WOM 中断阈值: 可配置 (典型 50-200 mg)
  ├─ WOM 检测延迟: 10-50 ms
  ├─ 唤醒后启动延迟: ~100 ms (时钟稳定等)
  └─ 恢复至 ACTIVE: 自动
```

**WOM (Wake-on-Motion) 详解**:

WOM 是 IMU 内部硬件大加速度检测机制：

```
IMU 内部
  ├─ 加速度计捕获 3 轴数据
  ├─ 计算 L2-范数 (√(x²+y²+z²))
  ├─ 与阈值比较
  ├─ 如果 > 阈值 → 触发 INT0 中断
  └─ CPU 在 INT0 中断处理器中唤醒

配置参数 (基于 IMU 型号):
  ├─ 加速度阈值: 50-500 mg (典型 100-200 mg)
  ├─ WOM 持续时间: 10-100 ms
  ├─ 丢弃样本: 初始几个样本 (防止伪触发)
  └─ 中断极性: 上升/下降沿
```

**重要**: WOM 不能无限期维持；需要设置超时以防止漂移：

```c
// 来自 power.c
#define DELAY_SLEEP_ON_STATUS  // 如果有活跃状态标志→延迟 WOM
CONFIG_SENSOR_LP_TIMEOUT = 3600000 ms  // 1 小时
```

**状态转换条件**:
```
LPM1 → ACTIVE (唤醒):
  ├─ IMU INT0 中断触发 (WOM 检测到运动) 
    OR
  ├─ 外部中断 (按钮)
    OR
  └─ 配置的超时过期
      └─ 进入 SYSTEM_OFF 或 LPM2

LPM1 → LPM2 (如启用):
  └─ CONFIG_SENSOR_LP_TIMEOUT 过期 (1 小时)
```

### 2.3 LPM2 (低功耗模式 2 - 扩展睡眠模式)

**启用条件**:
- LPM1 运行 1 小时无任何运动
- `CONFIG_SENSOR_USE_LOW_POWER_2 = y` (默认禁用)

**工作配置**:
```c
电源状态
  ├─ CPU: 离线 (仅系统定时器活跃)
  ├─ 无线电: 关闭
  ├─ IMU: 完全停用
  ├─ 所有实时约束: 解除
  ├─ 稳压器: LDO
  └─ 功耗: < 0.5 mA

同步问题:
  ├─ LPM2 中无法轮询传感器
  ├─ 需要定期唤醒以同步（增加延迟和功耗）
  ├─ 不适合实时应用
  └─ 仅推荐用于存放时间 > 1 天的设备
```

**为什么默认禁用**:
- 100ms 切换延迟对用户明显可感知
- 完全失去实时响应能力
- 通常未被采用（注释表示 "can be enabled for testing")

### 2.4 SYSTEM_OFF (深度睡眠/系统关机模式)

**启用条件**:
- 手动触发: 按钮长按 (>10s) 或控制台 `poweroff` 命令
- 自动触发: 活跃超时到期且启用了 `CONFIG_SHUTDOWN_ON_ACTIVE_TIMEOUT`
- 尝试初始化失败的设备

**工作配置**:
```c
电源状态
  ├─ CPU: 完全关闭
  ├─ 无线电: 关闭
  ├─ IMU: 关闭 (保留功耗数据)
  ├─ 所有 GPIO: 配置为高阻抗或下拉 (除唤醒源)
  ├─ 稳压器: 禁用 (直接从电池)
  ├─ Flash: 睡眠
  ├─ RAM: 仅保留数据部分活跃
  └─ 功耗: < 10 µA (理想 < 2 µA)

配置 (来自 Kconfig)
  ├─ CONFIG_USER_SHUTDOWN = y (启用该模式)
  ├─ CONFIG_IGNORE_CHARGE_WAKE_ON_VBUS = n
  │   └─ YES: VBUS 插入时不唤醒
  │   └─ NO:  VBUS 插入时 CHARGEDET GPIO 唤醒设备
  └─ 唤醒源 (可配置):
      ├─ GPIO (按钮)
      ├─ 运动检测 (如 IMU 支持)
      └─ 充电检测 (CHARGEDET GPIO)
```

**唤醒流程**:
```
设备在 SYSTEM_OFF 中
    ↓
唤醒源激活 (例如 GPIO 下降沿)
    ↓
nRF GPIO 唤醒电路激发
    ↓
系统复位 (类似硬件复位)
    ↓
Bootloader 启动
    ↓
应用固件启动 (main() 再次执行)
    ↓
从 retained 数据恢复状态
    ↓
重新初始化传感器和通信
    ↓
进入 ACTIVE 或 LPM1
```

## 4. 电力路径和稳压器管理

### 4.1 稳压器类型

**DCDC (直流-直流转换器)**:
```
优点:
  ├─ 能效高 (85-90%)
  ├─ 低输出纹波
  ├─ 支持宽输入电压范围
  └─ 同样输出电流时发热低

缺点:
  ├─ 静态电流较高 (~100-200 µA)
  ├─ 启动/稳定化时间较长 (~100 µA)
  ├─ 活跃时频率噪声
  └─ 不适合极低功耗应用

使用场景:
  └─ ACTIVE 和高流量 LPM1
```

**LDO (低损耗降压稳压器)**:
```
优点:
  ├─ 低静态电流 (1-5 µA)
  ├─ 快速启动 (无稳定时间)
  ├─ 低频噪声
  └─ 简单控制

缺点:
  ├─ 能效中等 (60-80%)
  ├─ 输出纹波较大
  ├─ 最大输入-输出压差限制
  └─ 不适合高电流应用

使用场景:
  └─ LPM1 和 LPM2 (低电流需求)
```

### 4.2 稳压器控制流程

```c
// 来自 power.c

sys_WOM():
  ├─ 禁用无线电 esb_deinitialize()
  ├─ 停用高频钟 clocks_stop()
  ├─ 停用传感器数据缓冲
  ├─ IF CONFIG_WOM_USE_DCDC = y
  │   └─ 保持 DCDC 激活 (更高效,但功耗高)
  │   └─ 理由：IMU 仍在运行，需要稳定 3.3V
  ├─ ELSE
  │   └─ 切换至 LDO (低漏电流)
  │   └─ GPIO 控制：nrf_gpio_pin_set(ldo_en.pin, 1)
  └─ 设置 IMU WOM 中断处理程序

// WOM 中断处理 (在 int0_handler 中)
imx_imu_int_handler():
  ├─ 清除中断标志
  ├─ 通知 sensor_thread (信号量)
  └─ 触发返回至 ACTIVE 的转换

sys_WOM_exit():
  ├─ 启动高频钟 clocks_start()
  ├─ IF CONFIG_WOM_USE_DCDC = n
  │   └─ 切换回 DCDC  (性能恢复)
  │   └─ GPIO 控制：nrf_gpio_pin_set(dcdc_en.pin, 1)
  │   └─ 等待 ~100 ms 稳定化
  ├─ IF nRF5340 或其他
  │   └─ 恢复频率缩放
  └─ 重启 esb_initialize()
```

### 4.3 电池电压检测与映射

```c
// 来自 battery.c 和 power.c

battery_poll():
  ├─ 采集 ADC 样本 24 次
  ├─ 计算滑动平均值

  ├─ ELSE IF CONFIG_BATTERY_USE_REG_LDO_MAPPING = y

  │       └─ 0%:   2.8V

  └─ ELSE
      └─ 禁用电池监控 (始终 100%)

电池追踪：
  ├─ battery_tracker.c 维护放电曲线

  ├─ 预测剩余使用时间
  └─ NVS 存储历史数据
```

## 5. 低功耗转换详细流程

### 5.1 从 ACTIVE 转换到 WOM

```c
// 初始化 WOM 模式的步骤

// 步骤1：评估条件 (power_thread)
elapsed_time = k_uptime_get() - last_activity_time;
IF (elapsed_time > CONFIG_ACTIVE_TIMEOUT_DELAY) AND
   (CONFIG_USE_IMU_WAKE_UP == y) AND
   (!pairing_mode) AND
   (status_flags & ERROR_MASK == 0):
    → 批准转换至 WOM
ELSE:
    → 保持 ACTIVE 或请求其他模式

// 步骤2：准备传感器 (sensor.c)
sensor_setup_WOM():
  ├─ 读取当前 IMU 配置
  ├─ 设置 WOM 阈值
  │   └─ 基于 IMU 型号：
  │       ├─ BMI270: reg 0x4C (INT_MAP1), 启用 WOM_INT
  │       ├─ ICM42688: reg 0x4F (INT_CONFIG1), WOM_INT
  │       └─ LSM6DSV: 特定寄存器配置
  ├─ 配置加速度 ODR (降至 12.5 Hz)
  └─ 启用 INT0 GPIO 中断

// 步骤3：停用无线电 (connection/esb.c)
esb_deinitialize():
  ├─ 清除 ESB TX/RX FIFO
  ├─ 关闭受杯器
  ├─ 禁用 RADIO 中断
  ├─ 配置无线电至 DISABLED 状态
  └─ 释放 radio 时钟

// 步骤4：时钟管理 (system/clock_control.c)
clocks_stop():
  ├─ 释放 HF 时钟请求
  ├─ 切换 LF 时钟从 LFXO → LF RC (节省电力)
  └─ 配置 CPU 进入 WFI (等待中断) 循环

// 步骤5：电源转换 (power.c)
IF CONFIG_WOM_USE_DCDC == n:
    ├─ nrf_gpio_pin_set(ldo_en, 1)      // LDO ON
    ├─ nrf_gpio_pin_set(dcdc_en, 0)     // DCDC OFF
    └─ mdelay(2)  // 稳定化延迟
ELSE:
    └─ 保持 DCDC 开启 (混合模式)

// 步骤6：清除中断标志
nrf_gpio_pin_configure_dt(&int0, GPIO_INPUT);  // INT0 输入模式
gpio_add_callback(&int0, imu_int_handler);     // 添加回调
gpio_pin_interrupt_configure_dt(&int0, GPIO_INT_EDGE_TO_ACTIVE);

LOG_INF("Entered WOM mode, current: ~1 mA");
```

### 5.2 从WOM唤醒到ACTIVE

```c
// WOM 中断处理程序

imu_int0_handler(device, cb, pins):
  ├─ 清除中断 (寄存器读取可能会清除)
  ├─ 记录唤醒时间戳
  ├─ 通知 sensor_thread 有新数据
  └─ 返回 (CPU 即将从 WFI 唤醒)

// sensor_thread 的唤醒处理
IF sensor_thread 在 WFI 中:
   ├─ 中断导致系统退出 WFI
   ├─ 继续执行
   └─ 周期 (2.5 ms) 拉取传感器

// 系统切换回 ACTIVE (power_thread)
sys_WOM_exit():
  ├─ clocks_start()      // 恢复 HF 时钟
  ├─ IF !CONFIG_WOM_USE_DCDC:
  │   ├─ nrf_gpio_pin_set(dcdc_en, 1)   // DCDC ON
  │   ├─ nrf_gpio_pin_set(ldo_en, 0)    // LDO OFF
  │   └─ mdelay(100)  // 等待 DCDC 稳定
  ├─ esb_initialize()     // 重启无线电
  ├─ 重置活动计时器
  └─ 设置状态为 ACTIVE

LOG_INF("Exited WOM, resumed ACTIVE mode, current: ~12 mA");
```

## 6. 中断和唤醒源

### 6.1 中断源映射

| 中断源 | GPIO | 优先级 | 处理 | 模式 |
|--------|------|--------|------|------|
| **IMU INT0 (WOM)** | 可配置 | 0 (高) | 唤醒至 ACTIVE | LPM1/LPM2 |
| **按钮 (sw0)** | 可配置 | 0 | 唤醒 + 命令 | 所有 |
| **USB VBUS** | GPIO 内部 | 1 | 唤醒 + 电源检测 | SYSTEM_OFF |
| **充电检测 (CHARGEDET)** | 可配置 | 1 | USB/充电事件 | SYSTEM_OFF (可选) |
| **UART 数据** | GPIO 内部 | 2 | 控制台 | ACTIVE |

### 6.2 多级唤醒优先级
```
等级 0 (立即唤醒):
  └─ IMU INT0 (运动检测) - 最常见

等级 1 (优先级唤醒):
  ├─ 按钮暴力唤醒
  └─ 系统故障 (WDT)

等级 2 (低优先级):
  └─ USB/充电事件 (缓慢响应 OK)
```

## 7. 看门狗集成

### 7.1 多通道看门狗

```c
// watchdog.c

watchdog_init():
  ├─ 硬件 WDT 配置：5000 ms (5 秒)
  ├─ 分配 8 个软件通道
  │   ├─ Ch0: sensor_thread (800 ms)
  │   ├─ Ch1: connection_thread (3000 ms)
  │   ├─ Ch2: power_thread (2000 ms)
  │   ├─ Ch3: button_thread (5000 ms)
  │   ├─ Ch4: console_thread (10000 ms)
  │   └─ Ch5-7: 预留
  └─ 启用 WDT

// 每个线程定期喂狗
sensor_thread():
  loop:
    ├─ 读取传感器
    ├─ watchdog_feed(WDT_CHANNEL_SENSOR)  // 每 800 ms
    └─ 延迟 100 ms

// WDT 超时处理
IF task_wdt_timeout():
    ├─ 记录失败的线程
    ├─ 记录堆栈跟踪
    └─ 系统复位 (由硬件 WDT 触发)
```

### 7.2 低功耗模式的 WDT 处理
```
ACTIVE 中: 正常 800 ms - 10000 ms 周期
LPM1 中:   
  └─ sensor_thread 不活跃，但...
     ├─ WDT 可能被禁用
     └─ 或周期扩展至秒级
SYSTEM_OFF: 所有线程停止，WDT 禁用
```

## 8. 电源配置参考

### 8.1 prj.conf 中的关键参数

```kconfig
# 电源管理基础
CONFIG_POWEROFF=y                      # 启用系统关机
CONFIG_REBOOT=y                        # 启用系统重启
CONFIG_RETAINED_MEM=y                  # 掉电保留数据

# 活跃超时
CONFIG_USE_ACTIVE_TIMEOUT=y            # 启用活跃超时
CONFIG_ACTIVE_TIMEOUT_DELAY=180000     # 3 分钟

# IMU 唤醒
CONFIG_USE_IMU_WAKE_UP=y               # 启用运动唤醒
CONFIG_SENSOR_LP_TIMEOUT=3600000       # 1 小时低功耗超时
CONFIG_USE_IMU_TIMEOUT=n               # 禁用 IMU 超时 (默认)
CONFIG_SENSOR_USE_LOW_POWER_2=n        # 禁用 LPM2

# 稳压器选择
CONFIG_WOM_USE_DCDC=n                  # WOM 使用 LDO (较低功耗)
                                       # = y 时更高效但功耗更大

# 看门狗
CONFIG_WATCHDOG=y
CONFIG_TASK_WDT=y
CONFIG_TASK_WDT_CHANNELS=8
```

### 9.2 逻辑分析器测量

使用逻辑分析器或示波器，可以测量：

```
电流消耗:
  ├─ ACTIVE: 12-15 mA
  ├─ LPM1 (WOM): 0.8-1.5 mA
  ├─ LPM2: < 0.5 mA
  └─ SYSTEM_OFF: < 10 µA

GPIO 行为:
  ├─ ACTIVE: DCDC_EN = 1, LDO_EN = 0
  ├─ LPM1: DCDC_EN = 0, LDO_EN = 1 (if CONFIG_WOM_USE_DCDC=n)
  └─ SYSTEM_OFF: 所有 GPIO 配置为睡眠状态

时间测量:
  ├─ ACTIVE 转
 WOM: ~100 ms
  ├─ WOM 唤醒 ACTIVE: ~50-100 ms (包括 IMU 读取)
  └─ 系统从 OFF 启动: ~500 ms
```

### 9.3 功耗优化建议

1. **禁用不需要的外设**:
   ```c
   pm_device_action_run(device, PM_DEVICE_ACTION_SUSPEND);
   ```

2. **使用 LDO 在 LPM1**:
   ```kconfig
   CONFIG_WOM_USE_DCDC=n  # 节省 ~2-4 mA
   ```

3. **增加活跃超时**:
   ```kconfig
   CONFIG_ACTIVE_TIMEOUT_DELAY=600000  # 10 分钟代替 3 分钟
   ```

4. **禁用磁力计** (如果不需要):
   ```c
   // 在 sensor.c 中有选项禁用
   CONFIG_SENSOR_ENABLE_MAG=n
   ```

5. **降低日志级别**:
   ```kconfig
   CONFIG_LOG_LEVEL_DBG=n  # 仅保留 INF/WRN/ERR
   ```

## 总结

该系统采用**四级电源模式**设计，在追踪性能和功耗间智能平衡。核心特性包括：

- **自动转换**: 基于活动超时和配置的自动电源模式切换
- **快速唤醒**: IMU 中断驱动的 < 100ms 响应时间
- **灵活稳压器**: DCDC/LDO 自适应选择
- **可靠性**: 多通道看门狗确保系统不卡死
- **用户控制**: 按钮触发的手动电源管理和 DFU 访问

得益于掉电保留数据，系统可以从任何电源状态恢复并保持校准和配对信息。
