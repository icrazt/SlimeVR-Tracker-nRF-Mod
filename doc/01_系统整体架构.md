# SlimeVR Tracker nRF 固件 - 系统整体架构

## 1. 项目概述

**项目名称**: SlimeVR-Tracker-nRF-Mod  
**项目性质**: 无线全身动作追踪器固件  
**目标平台**: Nordic nRF52/nRF54L 系列 SoC  
**操作系统**: Zephyr RTOS  
**授权方式**: MIT / Apache 2.0 双授权  

### 核心功能
- 6轴IMU（加速度+陀螺仪）多芯片支持
- 3轴磁力计融合（可选）
- VQF四元数融合算法实时处理
- Enhanced ShockBurst (ESB) 2.4GHz无线通信
- 多传感器同步时分多址 (TDMA)
- 完整的电源管理与低功耗模式
- USB HID 和 CDC ACM 接口
- 非易失性设置存储

## 3. 核心模块详解

### 3.1 传感器子系统 (`src/sensor/`)

├── imu/                    # IMU 驱动集合 (6种支持的芯片)

**主要功能流**:
```
系统启动
  ↓
sensor_init()              # 初始化传感器接口
  ├─→ 扫描 I2C 设备        # 自动检测 IMU 和磁力计
  ├─→ 初始化 IMU          # 配置加速度、陀螺、量程
  └─→ 初始化磁力计        # 配置磁力计采样率
        ↓
sensor_setup_WOM()         # 配置运动唤醒 (可选)
        ↓
主循环: sensor_read()      # 定期读取传感器数据
  ├─→ 读取 IMU FIFO
  ├─→ 读取磁力计
  ├─→ 应用校准数据
  └─→ 送入融合算法
```

### 3.2 通信子系统 (`src/connection/`)

**模块结构**:
```
connection/
├── connection.c/h          # 高层通信接口
│   ├─ connection_update_sensor_data()    # 发送四元数和加速度
│   ├─ connection_update_sensor_mag()     # 发送磁力计数据
│   └─ connection_update_battery()        # 发送电池状态
│
├── esb.c/h                # Enhanced ShockBurst 协议实现
│   ├─ esb_initialize()               # 初始化无线电
│   ├─ esb_deinitialize()             # 关闭无线电
│   ├─ esb_write()                    # 发送数据包
│   ├─ event_handler()                # ESB 事件回调
│   ├─ esb_reset_pair()               # 重置配对
│   └─ clocks_start() / clocks_stop() # 时钟管理
│
└── tdma.c/h               # 时分多址同步
    ├─ tdma_init()         # 初始化时同步
    └─ tdma_slot()         # 当前时间槽位
```

**通信流程**:
```
传感器数据 → connection_update_sensor_data()
              ↓
         构建数据包 (四元数 + 加速度)
              ↓
         esb_write() 发送到主站
              ↓
      (可选: 等待 ACK，如果启用)
```

**数据包格式**:
- **最大长度**: 48 字节 (可配置)
- **内容**: 四元数 (4×float)、加速度 (3×float)、设备ID、时间戳等
- **频率**: 400 Hz (对应陀螺仪采样率)

**电源模式状态机**:
```
    ┌─────────────┐
    │   ACTIVE    │  • 正常运行
    │  400Hz gyro │  • 无线电活跃
    │   Full CPU  │  • 所有 GPIO 启用
    └──────┬──────┘
           │ (3 分钟无活动 或主动请求)
           ↓
    ┌─────────────┐
    │    LPM1     │  • 运动唤醒 (WOM)
    │   IMU INT   │  • 陀螺 400Hz
    │   Only      │  • 加速度低频
    │  DCDC/LDO   │  • 电流 ~1mA
    └──────┬──────┘
           │ (1 小时无运动)
           ↓
    ┌─────────────┐
    │    LPM2     │  • 扩展低功耗 (可选)
    │   (可选)    │  • 更长的延迟
    │  DSP sleep  │
    └──────┬──────┘
           │ (1 小时超时或强制请求)
           ↓
    ┌─────────────┐
    │  SYSTEM OFF │  • 深度睡眠
    │  <10µA      │  • 按钮或运动唤醒
    │  NVM only   │  • 保留数据持久化
    └─────────────┘
```

### 3.4 系统初始化流程 (`main.c`)

```
main()
  ├─→ 步骤1: GPIO 配置
  │    └─ 设置电源 GPIO (pwr/gnd pins)
  │
  ├─→ 步骤2: 重启原因检测
  │    ├─ 检查 RESETREAS 寄存器
  │    ├─ 判断重启是否来自按钮
  │    └─ 清除 RESETREAS 标志
  │
  ├─→ 步骤3: LED 启动指示
  │    └─ set_led(SYS_LED_PATTERN_ON)
  │
  ├─→ 步骤4: 重启计数器管理
  │    ├─ 读取重启计数器 (NVS 存储)
  │    ├─ 计算 reset_mode = reboot_counter - 100
  │    └─ 后续交给 sys_reset_mode(reset_mode) 处理按钮多按模式
  │
  ├─→ 步骤5: 按钮检测 (可选)
  │    ├─ IF 按钮未被按住
  │    │   └─ 正常启动继续
  │    ├─ ELSE IF 按钮被按住 < 5秒
  │    │   └─ 启动时 LED 闪烁，继续启动
  │    ├─ ELSE IF 按钮被按住 5-10秒
  │    │   ├─ esb_reset_pair() → 重置配对
  │    │   └─ 继续启动
  │    └─ ELSE
  │        └─ 按钮释放后继续启动
  │
  ├─→ 步骤6: 系统状态恢复
  │    ├─ 从 NVS 读取：配对地址、RF 频道、校准数据
  │    └─ 恢复 retained_data (断电保留数据)
  │
  └─→ 步骤7: 启动重要线程
       ├─ 传感器读取线程 (sensor_thread)
       ├─ 通信线程 (connection_thread)
       ├─ 电源管理线程 (power_thread)
       ├─ 看门狗线程 (watchdog_thread)
       ├─ TCP console 线程 (console_thread)
       └─ 其他系统线程
```

## 4. 数据流向关键路径

### 4.1 传感器数据流

```
硬件传感器
    ↓
I2C/SPI 接口读取
    ↓
IMU interface (imu_read)
    ├─→ 原始数据 → 单位转换
    ├─→ 应用加速度偏移校准
    ├─→ 应用陀螺偏移校准
    └─→ 应用温度补偿 (T-Cal)
    ↓
传感器融合 (VQF)
    ├─→ 输入: 加速度 (g), 陀螺 (rad/s), 磁力计 (T)
    ├─→ 内部: 四元数滤波计算
    └─→ 输出: 四元数 (w,x,y,z)
    ↓
connection_update_sensor_data()
    ├─→ 构建 ESB 数据包
    ├─→ 添加四元数和线性加速度
    └─→ 队列到无线电发送
    ↓
ESB 协议队列
    ├─→ 包装 ESB 帧头
    ├─→ 配置 RF 频率和功率
    └─→ 发送到 nRF 无线电 FIFO
    ↓
2.4GHz 空中传输
    ↓
主站接收
```

### 4.2 电源状态转换路径

```
活跃状态 (ACTIVE)
    │
    ├─ IF 3分钟无数据 AND 启用 WOM AND 不在配对模式
    │  └─→ sys_request_WOM()
    │      ├─ 停用无线电
    │      ├─ 配置 IMU 运动检测整数
    │      ├─ 停用高频钟
    │      └─ 设置为 WOM 模式 (低功耗1)
    │
    ├─ IF 1 小时无运动 AND 启用 LPM2
    │  └─→ 进入 LPM2 (更深睡眠)
    │
    └─ IF 手动或日志记录请求 system_off
       └─→ sys_request_system_off()
           ├─ 禁用所有 GPIO
           ├─ 停用传感器
           ├─ 配置唤醒源 (按钮/充电/运动)
           └─ 调用 sys_poweroff()
```

## 5. 多线程架构

**Zephyr 线程清单**:

| 线程名 | 优先级 | 堆栈大小 | 主要功能 |
|--------|--------|---------|----------|
| `main` | 0 | 2048B | 应用初始化 |
| `sensor_thread` | 4 | 2048B | 定期读取和融合传感器数据 |
| `connection_thread` | 4 | 1024B | ESB 通信和数据包发送 |
| `power_thread` | 6 | 1024B | 电源管理和状态转换 |
| `watchdog_thread` | 6 | (多通道) | 多线程看门狗监视 |
| `console/uart_thread` | 7 | 512B | 交互式控制台命令 |
| `button_thread` | 5 | 512B | 按钮事件处理 |
| `system_workqueue` | 7 | 512B | 系统后台任务 |

**线程间通信**:
- **Mutexes**: 保护共享数据 (retained_data, calibration)
- **Semaphores**: 事件同步 (新传感器数据、电源事件)
- **Message Queues**: 异步通信 (按钮事件→电源管理)
- **Shared Memory**: retained_data 结构体

### 6.3 非易失性数据结构 (retained.h)
该结构体跨系统重启/WOM 唤醒持久化：

```c
struct retained_data {
    uint32_t build_timestamp;           // 固件版本
    uint64_t uptime_latest;             // 最新运行时
    uint64_t uptime_sum;                // 累计运行时
    
    // 电池统计
    int16_t max_battery_pptt;           // 最高电压 (parts per ten thousand)
    int16_t min_battery_pptt;           // 最低电压
    int16_t battery_pptt_curve[18];     // 放电曲线
    
    // 配对和通信
    uint8_t paired_addr[8];             // 搭配的接收器地址
    uint8_t rf_channel;                 // RF 频道 (0-100)
    
    // 校准数据 (关键)
    float accelBias[3];                 // 加速度偏移
    float gyroBias[3];                  // 陀螺偏移
    float magBias[3];                   // 磁力计偏移
    float magBAinv[4][3];               // 磁力计软铁矫正矩阵
    float accBAinv[4][3];               // 加速度软铁矫正矩阵
    
    // 融合状态
    uint8_t fusion_id;                  // 融合算法ID (VQF/xiofusion)
    uint8_t fusion_data[512];           // 融合算法的保留状态
    
    // 温度校准 (T-Cal)
    float gyroTemp;                     // 上次测量的温度
    struct TempCalPoint tempCalPoints[TCAL_BUFFER_SIZE]; // 温度桶 + 三轴 bias
    float tempCalCoeffs[3][POLY_DEGREE+1];               // 兼容保留字段，当前 MLS/LUT 不使用
    struct { ... } tempCalState;         // 点数、有效状态
    struct { ... } bootCalState;         // 启动/运行时 D_offset 状态
    
    // 设备信息
    uint16_t imu_addr;                  // IMU 芯片地址/ID
    uint16_t mag_addr;                  // 磁力计芯片地址/ID
}
```

## 7. 复位和启动模式

### 7.1 复位原因分类
```
NRF_RESET->RESETREAS 寄存器 (或 NRF_POWER->RESETREAS)
    │
    ├─ RESETPIN = 1  → 硬件复位脚触发 (无关按钮)
    ├─ RESETPIN = 0  → 其他原因
    │   ├─ 正常启动 (冷启动)
    │   ├─ WDT 超时引起
    │   └─ 软件请求重启
    │
    └─ button_read() = 1  → 按钮当前被按住
        └─ 配合时间判断启动模式
```

### 7.2 启动模式

| 场景 | 条件 | 动作 |
|------|------|------|
| **正常启动** | 无按钮/ RESETPIN | 正常启动，继续初始化 |
| **复位配对** | 按钮 5-10 秒 | 调用 `esb_reset_pair()`，清除配对地址 |
| **普通 DFU** | 控制台 `dfu`、按钮多按、远程 `ESB_PONG_FLAG_DFU` | 设置 UF2 magic 或 nRF5 bootloader 触发条件并重启 |
| **BLE OTA DFU** | 控制台 `dfu ota`、按钮多按、远程 `ESB_PONG_FLAG_DFU_OTA` | 设置 Adafruit OTA magic 并重启 |
| **从关机恢复** | reboot_counter=0 + 按钮 | 从 SYSTEM_OFF 唤醒，继续启动 |
| **WDT 恢复 DFU** | 连续 WDT 复位达到 `WATCHDOG_RESET_THRESHOLD` | 自动进入普通 DFU 用于恢复 |

## 9. DFU (固件更新) 机制

### 9.1 进入 DFU 的触发条件
1. **控制台命令**: `dfu` 进入普通 DFU，`dfu ota` 进入 BLE OTA DFU。入口: `src/console.c::console_thread()`。
2. **按钮多按**: `src/system/system.c::button_thread()` 统计按键次数后调用 `sys_reset_mode()`。普通板卡 4-5 次进入普通 DFU；Styria Mini UF2 为 6-7 次；8-9 次进入 BLE OTA。
3. **USB 初始化时按住按钮**: `src/console.c::console_thread()` 检测 `button_read()` 后进入普通 DFU。
4. **远程预置命令**: `ESB_PONG_FLAG_DFU` / `ESB_PONG_FLAG_DFU_OTA`。定义: `src/connection/esb.h`；执行: `src/connection/esb.c`。
5. **看门狗恢复**: 连续 WDT 复位达到 `src/system/watchdog.h::WATCHDOG_RESET_THRESHOLD` (当前 3) 后，`src/system/watchdog.c::enter_dfu_mode()` 进入普通 DFU。

### 9.2 DFU 标志存储
```
普通 UF2 DFU:
  NRF_POWER->GPREGRET = ADAFRUIT_DFU_MAGIC_UF2_RESET  // 0x57

BLE OTA DFU:
  NRF_POWER->GPREGRET = ADAFRUIT_DFU_MAGIC_OTA_RESET  // 0xA8

双重复位保留位:
  DFU_DBL_RESET_MEM = 0x20007F7C
  DFU_DBL_RESET_APP = 0x4ee5677e
  当前应用侧主要用于告诉 Adafruit bootloader 跳过双重复位 DFU。

代码对照:
  • src/globals.h
  • src/main.c
  • src/system/power.c::disable_DFU_thread()
```

### 9.3 Bootloader 选择
- **Adafruit UF2**: `CONFIG_BUILD_OUTPUT_UF2 = y` → UF2 文件格式
- **Adafruit BLE OTA**: 同一 bootloader 下通过 `dfu ota` / `ESB_PONG_FLAG_DFU_OTA` 进入 OTA 模式
- **nRF5 Bootloader**: `CONFIG_BOARD_HAS_NRF5_BOOTLOADER = y` → 二进制/串口更新路径，BLE OTA magic 不适用

## 总结

该系统采用**模块化和分层设计**，确保各子系统独立运作同时通过清晰的接口交互。核心创新包括：

1. **多芯片支持**: 灵活的传感器驱动框架支持多种 IMU 和磁力计
2. **实时融合**: VQF 算法在 nRF 上实时处理四元数输出
3. **电源效率**: 多层电源模式由低功耗唤醒系统驱动，在保留功能和待机时间间取得平衡
4. **可靠性**: 多通道看门狗、CRC 校验、掉电保留数据确保系统稳定
5. **用户友好**: 交互式控制台、LED 状态反馈、按钮多功能
