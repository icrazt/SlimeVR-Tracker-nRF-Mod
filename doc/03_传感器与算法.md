## 2. 传感器初始化流程

### 2.1 自动检测机制

```c
// src/sensor/sensor.c - sensor_init()

sensor_init():
  ├─ 步骤1: 扫描 I2C 设备
  │   └─ sensor_scan()
  │       ├─ 公共 I2C 地址范围遍历 (0x00-0x7F)
  │       ├─ 匹配已知的 IMU/MAG 芯片 ID
  │       └─ 记录找到的设备: imu_addr, mag_addr
  │
  ├─ 步骤2: 扫描 SPI 设备 (如果配置)
  │   └─ sensor_scan_spi()
  │       ├─ 轮询 SPI 总线
  │       └─ 读取芯片 ID 寄存器
  │
  ├─ 步骤3: 初始化 IMU
  │   └─ interface_init_imu()
  │       ├─ 读取 WHO_AM_I 寄存器确认芯片
  │       ├─ 对照 imu_drivers 表
  │       ├─ 调用具体驱动的 init()
  │       │   ├─ BMI270_init()
  │       │   ├─ ICM42688_init()
  │       │   ├─ LSM6DS*_init()
  │       │   └─ ICM45686_init()
  │       └─ 配置 ODR、量程、中断
  │
  ├─ 步骤4: 初始化磁力计 (可选)
  │   └─ interface_init_mag()
  │       ├─ 读取 WHO_AM_I 确认芯片
  │       ├─ 调用具体驱动的 init()
  │       └─ 配置 ODR、测量模式
  │
  ├─ 步骤5: 从 NVS 恢复校准数据
  │   └─ retained_data
  │       ├─ accelBias[3]
  │       ├─ gyroBias[3]
  │       ├─ magBias[3]
  │       ├─ 6 边校准矩阵
  │       └─ T-Cal 温度点、MLS 状态和兼容保留字段
  │
  └─ 步骤6: 初始化融合算法
      └─ fusion_init()
          ├─ VQF 初始化 (默认)
          └─ 或 xiofusion 初始化
```

**关键点**:
- 芯片检测通过 WHO_AM_I 寄存器进行
- 支持热插拔改变 (在某些板上)
- 如果检测失败，会记录错误并尝试下一个驱动

## 3. 传感器读取流程

### 3.1 主传感器线程循环

```c
// 传感器数据流水线 (400 Hz = 2.5 ms 周期)

sensor_thread():
  while (true):
    ├─ k_sleep(K_MSEC(2.5))    // 2.5 ms = 400 Hz 周期
    │
    ├─ IF sensor_ready:
    │   │
    │   ├─ 步骤1: 读取 IMU FIFO
    │   │  interface_read_imu_fifo()
    │   │   ├─ 检查 FIFO 计数
    │   │   ├─ 批量读取 N 个样本 (典型 1-4)
    │   │   ├─ 单位转换: 原始 → SI
    │   │   │   ├─ 加速度: LSB → m/s²
    │   │   │   └─ 陀螺: LSB → rad/s
    │   │   └─ 返回: samples[count]
    │   │
    │   ├─ 步骤2: 应用加速度校准
    │   │  sensor_calibration_process_accel(accel)
    │   │   ├─ 减去 accelBias
    │   │   ├─ 应用 AccBAinv 矩阵 (6 边校准)
    │   │   └─ 结果: 校准加速度
    │   │
    │   ├─ 步骤3: 应用陀螺校准
    │   │  sensor_calibration_process_gyro(gyro)
    │   │   ├─ 减去 gyroBias
    │   │   ├─ 应用温度补偿 (T-Cal)
    │   │   │   └─ gyroBias_corrected = 
    │   │   │       LUT lookup → MLS fallback → static gyroBias
    │   │   └─ 结果: 校准陀螺
    │   │
    │   ├─ 步骤4: 读取磁力计 (100 Hz)
    │   │  IF (sample_count % 4 == 0):  // 400 Hz / 4 = 100 Hz
    │   │   interface_read_mag(mag)
    │   │   ├─ 一般为一次读 + 缓存
    │   │   ├─ 单位转换: LSB → µT
    │   │   ├─ 应用磁力计校准
    │   │   │   ├─ 减去 magBias
    │   │   │   └─ 应用 MagBAinv 矩阵 (软铁变换)
    │   │   └─ 使用最新的有效磁力计值
    │   │
    │   ├─ 步骤5: 送入融合算法
    │   │  vqf_update(
    │   │      accel_cal, gyro_cal, mag_cal,
    │   │      dt = 2.5 ms,
    │   │      imu_temp
    │   │  )
    │   │   ├─ VQF 内部处理
    │   │   └─ 输出: 四元数 [w, x, y, z]
    │   │
    │   ├─ 步骤6: 读取温度 (每 1000 ms)
    │   │  IF (sample_count % 400 == 0):
    │   │   interface_read_temperature(temp)
    │   │   └─ 用于 T-Cal 和监控
    │   │
    │   └─ 步骤7: 发送至连接层
    │      connection_update_sensor_data(quaternion, accel)
    │       └─ 入队至 ESB 发送
    │
    ├─ 喂狗
    │  watchdog_feed(WDT_CHANNEL_SENSOR)
    │
    └─ 检查请求 (校准、电源模式等)
```

### 3.2 加速度和陀螺的单位转换

```c
// 来自 interface.c 中的驱动实现

// BMI270 示例
BMI270_get_accel_data(float accel[3]):
  ├─ 读取 ACC_X_LSB, ACC_X_MSB (16-bit 有符号)
  ├─ 读取 ACC_Y_LSB, ACC_Y_MSB
  ├─ 读取 ACC_Z_LSB, ACC_Z_MSB
  └─ 转换 (对于 ±16g 范围):
      accel[0] = raw_x * 16.0 / 32768.0  // m/s²
      accel[1] = raw_y * 16.0 / 32768.0
      accel[2] = raw_z * 16.0 / 32768.0

// 陀螺转换 (对于 ±4000 dps 范围)
BMI270_get_gyro_data(float gyro[3]):
  ├─ 读取 GYR_X_LSB, GYR_X_MSB (16-bit 有符号)
  ├─ 读取 GYR_Y_LSB, GYR_Y_MSB
  ├─ 读取 GYR_Z_LSB, GYR_Z_MSB
  └─ 转换:
      gyro[0] = raw_x * 4000.0 / 32768.0 * M_PI / 180.0  // rad/s
      gyro[1] = raw_y * 4000.0 / 32768.0 * M_PI / 180.0
      gyro[2] = raw_z * 4000.0 / 32768.0 * M_PI / 180.0
```

## 4. VQF (向量四元数滤波器) 算法

### 4.1 VQF 概述

**什么是 VQF？**

Vector Quaternion Filter (VQF) 是一种轻量级的 IMU 融合算法，特别适合嵌入式系统：

- **输入**: 加速度、陀螺、磁力计 (3D 向量)
- **输出**: 四元数 (w, x, y, z) 表示的姿态
- **计算**: ~1 ms 在 Cortex-M4 @ 64 MHz
- **优势**: 低复杂度、快速收敛、磁干扰抗性强

**四元数表示**:
```
q = [w, x, y, z] 其中:
    w: 标量部分 (实部)
    x, y, z: 向量部分 (虚部)
    
欧拉角转换:
    roll  = atan2(2*(w*x + y*z), 1 - 2*(x² + y²))
    pitch = asin(2*(w*y - z*x))
    yaw   = atan2(2*(w*z + x*y), 1 - 2*(y² + z²))
```

### 4.2 VQF 外部库集成

该项目使用外部 C 库 `vqf-c`:

```
vqf-c/ (子模块)
├── VQF.c / VQF.h       # 核心算法实现
├── VQF_config.h        # 配置参数
└── ...

src/sensor/fusion/vqf/
└── vqf.c / vqf.h       # SlimeVR 包装
    ├─ vqf_init()

    ├─ vqf_update_full()         // 全 IMU+磁力计 (9-DOF)
    └─ vqf_get_quaternion()
```

### 4.3 VQF 初始化和参数

```c
// src/sensor/fusion/vqf/vqf.c

vqf_init():
  ├─ 初始化四元数为单位四元数
  │  q = [1, 0, 0, 0]  // 与地球坐标系对齐
  │
  ├─ 初始化 VQF 内部状态
  │  vqf_state = {
  │      q = [1, 0, 0, 0],  // 当前四元数
  │      gyro_bias = [0, 0, 0],  // 陀螺零偏
  │      ...
  │  }
  │
  ├─ 设置融合参数
  │  vqf_params.setGyrAccTime = 0.5;  // 陀螺/加速力融合时间常数
  │  vqf_params.setMagTime = 0.5;     // 磁力计融合时间常数
  │  vqf_params.tauAcc = 0.1;         // 加速度噪声常数
  │  vqf_params.tauMag = 0.1;         // 磁力计噪声常数
  │
  └─ 就绪进行更新循环

// VQF 参数含义
tauAcc:         // 加速度信任权重 (越小越信任加速度)
                // 适用于反转定义坐标系和重力
                // 典型: 0.1-1.0 秒

tauMag:         // 磁力计信任权重
                // 适用于磁偏角修正
                // 典型: 0.1-1.0 秒

setGyrAccTime:  // 陀螺仪/加速度融合响应时间
                // 越短 → 越快响应加速度变化
                // 越长 → 对加速度噪声越鲁棒
                // 典型: 0.5-2.0 秒

setMagTime:     // 磁力计融合响应时间
                // 越短 → 越快修正偏航角漂移
                // 越长 → 对磁干扰越鲁棒
                // 典型: 0.5-2.0 秒
```

### 4.4 VQF 更新循环

```c
// 在传感器线程中 (每 2.5 ms)

IF using_magnetometer:
    vqf_update_full(
        accel,          // 加速度 [x, y, z] in m/s²
        gyro,           // 陀螺 [x, y, z] in rad/s
        mag,            // 磁力计 [x, y, z] in µT
        dt = 0.0025,    // 时间差 (秒)
        temp            // 温度 (用于温度补偿)
    )
ELSE:
    vqf_update_imu(
        accel,
        gyro,
        dt
    )

// VQF 内部处理 (简化流程)
VQF.update():
  ├─ 陀螺仪积分 (纯陀螺预测)
  │  q_gyr = integrate_quaternion(q_old, gyro, dt)
  │  └─ 用陀螺角速度更新四元数
  │
  ├─ 加速度修正 (重力向量)
  │  g_accel = extract_gravity(accel)
  │  q_acc_correction = align_vectors(g_accel, [0,0,1])
  │  └─ 检测偏离垂直平面的倾斜
  │
  ├─ 磁力计修正 (北向向量) - 如果启用
  │  m_corrected = apply_soft_iron(mag, magBAinv)
  │  m_earth = rotate_by_quaternion(m_corrected, q)
  │  q_mag_correction = align_vectors(m_earth, [B_x, 0, B_z])
  │  └─ 修正偏航角漂移
  │
  ├─ 融合权重 (基于时间常数)
  │  w_acc = min(dt / (tau_acc + dt), 1.0)
  │  w_mag = min(dt / (tau_mag + dt), 1.0)
  │
  ├─ 四元数线性混合 (SLERP 的近似)
  │  q_out = slerp(q_gyr, q_acc_correction, w_acc)
  │  IF mag_enabled:
  │      q_out = slerp(q_out, q_mag_correction, w_mag)
  │
  └─ 规范化和输出
     q_out = normalize(q_out)
     return q_out
```

## 5. 校准系统

### 5.1 三层校准架构

```

                  ↓
┌─────────────────────────────────────┐

│  • 矩阵计算                          │
│  • 系数拟合                          │
└─────────────────┬───────────────────┘
                  ↓
┌─────────────────────────────────────┐
│  retained.h (非易失存储)             │
│  • accelBias, gyroBias, magBias     │

```

### 5.2 6 边加速度校准 (0g 偏移和软铁矫正)

**目标**: 消除加速度零偏和非正交性

**原理**:
```
原始代表的重力 = [x_raw - mx, y_raw - my, z_raw - mz]  (偏移)
               = inv(M) · [x_raw - mx, y_raw - my, z_raw - mz]  (软铁)
               = 地球坐标系中的重力 [0, 0, 1] (单位: g)

其中:
  mx, my, mz: 加速度零偏 (bias)
  M: 3×3 软铁矫正矩阵 (缩放和正交化)
```

**校准流程** (来自 `sensor_request_calibration(SENSOR_CAL_ACCEL_6SIDE)`):

```c
6_side_calibration():
  ├─ 初始化: 6 个向量采集缓冲区
  │   ├─ +X 方向 (设备 X 轴朝上)
  │   ├─ -X 方向
  │   ├─ +Y 方向
  │   ├─ -Y 方向
  │   ├─ +Z 方向
  │   └─ -Z 方向
  │
  ├─ 对每个方向:
  │   ├─ 用户物理定位设备
  │   ├─ 系统采集 100-1000 个原始样本
  │   ├─ 计算该方向的平均加速度向量
  │   └─ 存储至方向缓冲区
  │
  ├─ 数据收集后:
  │   ├─ 计算 6 个向量的均值 (理想应为 [±1, 0, 0], [0, ±1, 0], [0, 0, ±1])
  │   ├─ 建立线性方程组: A·x = b
  │   │   其中 A 是 6 个向量矩阵
  │   │   x 是未知的偏移和缩放系数
  │   │   b 是期望的方向向量
  │   │
  │   └─ 解线性方程组以获得软铁矫正矩阵
  │
  └─ 存储结果:
     ├─ accBias = [mx, my, mz]
     └─ accBAinv = (1/scale) * 正交化矩阵
```

**实际使用**:
```c
sensor_calibration_process_accel(raw_accel):
  temp = raw_accel - accBias
  raw_accel = accBAinv · temp
  // 结果: cal_accel 现在是地球坐标系中的加速度
```

### 5.3 T-Cal (温度校准)

**目标**: 补偿陀螺仪随温度变化的零偏

**当前实现**:
```
gyro_bias_effective(T) =
  1. 优先使用 LUT: 对固定温度网格中的 MLS 结果做线性插值
  2. LUT 未就绪时回退 MLS: 在当前温度附近做局部加权线性拟合
  3. T-Cal 数据不足时回退 static gyroBias
  4. 如果启动/运行时校准产生 D_offset，则叠加到最终 bias

代码对照:
  • src/sensor/calibration.c::sensor_calibration_process_gyro()
  • src/sensor/calibration.c::sensor_tcal_lut_lookup()
  • src/sensor/calibration.c::sensor_tcal_mls_lookup()
  • src/sensor/calibration.c::sensor_tcal_calculate_doffset()
```

**自动 T-Cal 流程**:

```c
// src/sensor/sensor.c::sensor_thread()
IF resting:
    sensor_tcal_check_auto_calibration(current_temp)
ELSE:
    sensor_tcal_continuous_motion_detected()

// src/sensor/calibration.c::sensor_calibration_process_gyro()
IF tcal_auto_calibration_enabled:
    sensor_tcal_feed_continuous_sample(raw_gyro, current_temp)
    ├─ 温度必须在 CONFIG_SENSOR_POLY_TEMP_MIN/MAX 范围内
    ├─ 陀螺三轴范围超过 TCAL_ACCUM_GYRO_RANGE_THRESHOLD 视为运动，丢弃窗口
    ├─ 每约 25 秒 flush 一次，或温度漂移超过约 0.53°C 时提前 flush
    ├─ 样本写入对应温度桶 tempCalPoints[index]
    └─ update_tcal_state() 使 MLS/LUT 缓存失效并保存到 NVS

// 运行时应用
sensor_calibration_process_gyro(raw_gyro, current_temp):
  bias_at_temp = LUT(current_temp) or MLS(current_temp) or gyroBias
  bias_at_temp += D_offset if valid
  raw_gyro = raw_gyro - bias_at_temp
```

**T-Cal 配置参数**:
```c
CONFIG_SENSOR_USE_TCAL=y                    // 启用
CONFIG_SENSOR_POLY_DEGREE=3                 // Kconfig 默认；当前仅影响兼容保留数组尺寸
CONFIG_SENSOR_POLY_TEMP_MIN=10              // 最低温度 (°C)
CONFIG_SENSOR_POLY_TEMP_MAX=45              // 最高温度 (°C)
CONFIG_SENSOR_POLY_STEPS_PER_DEGREE=2       // 每摄氏度的温度桶数量，2 = 0.5°C 间隔

// T-Cal 缓冲区大小
TCAL_BUFFER_SIZE = (45-10) * 2 = 70 个温度点

// 代码对照:
//   Kconfig: SENSOR_USE_TCAL / SENSOR_POLY_*
//   src/retained.h: TCAL_BUFFER_SIZE, tempCalPoints, tempCalState
//   src/sensor/calibration.c: update_tcal_state()
```

**控制台操作**:

### 5.4 启动校准 (陀螺偏移)

**目标**: 每次启动时清除陀螺仪零偏漂移

**配置**:
```c
CONFIG_SENSOR_USE_BOOT_CALIBRATION=n  // 默认禁用
                                       // 可通过 tcal boot on 在运行时开启
```

**流程**:
```c
IF bootCalState.enabled and !completed:
    ├─ 仅在启动后 5-30 秒窗口内尝试
    ├─ 必须已有足够 T-Cal 数据 (> 4 个点且当前温度质量合格)
    ├─ 设备静止后采集当前 bias
    ├─ 用 T-Cal 曲线计算该温度的期望 bias
    ├─ D_offset = measured_bias - tcal_bias
    └─ 后续陀螺校准中叠加 D_offset

  • src/sensor/calibration.c::sensor_perform_boot_calibration()
```


## 8. 算法调优与校准方法

### 8.1 精度优化步骤

**第 1 步: 静态准确性 (放置设备)**

```
目标: 在静止状态下，四元数应该反映正确的物理方向

方法:
  1. 将设备放在平坦表面，X 轴朝向您
  2. 运行 6 边加速度校准
  3. 检查四元数输出
     • X 轴版本: q = [0.707, 0.707, 0, 0]  (±90° 翻滚)
     • Y 轴版本: q = [0.707, 0, 0.707, 0]  (±90° 俯仰)
     • Z 轴版本: q = [1, 0, 0, 0]          (无旋转)

故障排查:
  • 四元数不变化 → 加速度没有应用，检查校准
  • 四元数漂移 → 陀螺零偏大，运行 T-Cal
  • 非线性角度 → 可能硬铁干扰 (罕见)
```

**第 2 步: 磁偏角校准**

```
目标: 确保偏航角反映北向

方法:
  1. 将设备放在平坦表面
  2. 知道当前的磁北偏角 (如果未知，可用手机罗盘)
  3. 旋转设备 360° 同时记录四元数
  4. 绘制偏航角 vs 物理方向
     • 理想: 线性 1:1 映射
     • 非线性 → 软铁干扰 → 运行 6 边磁力计校准

磁力计校准:
  • 类似加速度 6 边校准
  • 但方向为北、东、上
  • 需要在原地旋转设备
```

**第 3 步: 动态精度 (运动中)**

```
目标: 在快速运动中，四元数应准确跟踪方向

方法:
  1. 快速旋转设备 (50-200°/s)
  2. 停止并检查四元数是否收敛
  3. 通常应在 1-2 秒内收敛到最终值

参数调整:
  • 如果收敛太慢 → 减小 tau_acc, tau_mag (快速响应)
  • 如果抖动过大 → 增大 tau_acc, tau_mag (更稳定)
  • 如果偏航漂移 → 传感器或磁干扰问题

VQF 参数 (来自 vqf.h):
  vqf_params.setGyrAccTime = 0.5;  // 0.2-2.0 秒范围
  vqf_params.setMagTime = 0.5;     // 0.2-2.0 秒范围
  vqf_params.tauAcc = 0.1;         // 0.05-0.5 秒范围
  vqf_params.tauMag = 0.1;         // 0.05-0.5 秒范围
```

### 8.2 T-Cal 优化

```
理想 T-Cal 采集:
  1. 先运行 tcal clear 清掉明显错误的旧数据 (可选)
  2. 运行 tcal auto on
  3. 让设备静止，避免桌面振动和手持移动
  4. 缓慢覆盖 10°C 到 45°C 范围，默认每 0.5°C 一个温度桶
  5. 期间用 tcal status / tcal dump 检查点数和温度范围
  6. 发现离群点时用 tcal remove <index> 删除
  7. 完成后运行 tcal auto off

效果验证:
  • tcal check: 检查当前温度是否离最近校准点太远
  • tcal test [temp]: 查看 MLS 输出和最终应用 bias
  • info: 查看实时 Gyroscope bias tcal

代码对照:
  • src/sensor/calibration.c::sensor_tcal_feed_continuous_sample()
  • src/sensor/calibration.c::tcal_accum_flush()
  • src/sensor/calibration.c::sensor_tcal_test_methods()
```

```
  • ESB 发送: ~1.0-2.0 ms

  • SYSTEM_OFF: < 10 µA
```

## 总结

该系统的传感器和融合架构是**生产级别的**，具有：

1. **灵活的多芯片支持**: 支持 6 种 IMU 和 9 种磁力计，自动检测和初始化
2. **完整的校准系统**: 6 边加速度校准、温度补偿 (T-Cal)、启动校准
3. **高效的融合算法**: VQF 提供快速、准确的房间级追踪
4. **鲁棒的噪声处理**: FIFO 缓冲、传感器融合权重、磁干扰检测
5. **广泛的可配置性**: KConfig 选项允许针对不同的 IMU 和应用场景进行优化

核心设计确保了在消费类电子产品和运动追踪中的可靠性。
